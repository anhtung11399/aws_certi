Deploy và vận hành ứng dụng

Chiến lược deploy, Elastic Beanstalk, CodeDeploy, ECS / EKS / Lambda ở góc vận hành, automation hướng sự kiện.

Học xong bài này bạn sẽ:
  • Chọn chiến lược deploy theo yêu cầu
  • Vận hành container và serverless
  • Dựng automation hướng sự kiện

ImmutableDựng nhóm máy mới hoàn toàn, khoẻ thì chuyển, xoá cũKhôngNhanh: xoá nhóm mớiGấp đôi trong lúc deploy

  • Elastic Beanstalk có sẵn các kiểu trên (all at once, rolling, rolling with additional batch, immutable, traffic splitting). Blue/green trong Beanstalk = tạo môi trường thứ hai rồi swap environment URLs.
  • CodeDeploy: EC2 / on-premises (in-place hoặc blue/green với ASG), Lambda (canary / linear / all-at-once, chuyển traffic giữa alias version), ECS (blue/green qua ALB). Có tự rollback khi CloudWatch alarm kêu. File appspec.yml định nghĩa các hook (BeforeInstall, AfterInstall, ApplicationStart, ValidateService).
  • Lambda: dùng version (bất biến) và alias (con trỏ, có weighted routing giữa hai version).
  • Database thay đổi lược đồ: chú ý cả hai phiên bản cùng chạy trong lúc blue/green. RDS Blue/Green Deployments cho nâng cấp phiên bản engine với downtime rất ngắn.

#Elastic Beanstalk chi tiết

  • Thành phần: application → application version (gói code trên S3) → environment (web server hoặc worker tier dùng SQS).
  • Cấu hình bằng .ebextensions/*.config (YAML: gói cần cài, file, lệnh, tài nguyên CloudFormation thêm), .platform/hooks trên nền tảng Amazon Linux 2023, saved configuration.
  • Đừng tạo RDS bên trong environment cho production (xoá environment là mất database); tạo RDS riêng và truyền endpoint qua biến môi trường.
  • Kiểu deploy: All at once, Rolling, Rolling with additional batch, Immutable, Traffic splitting (canary theo % trong thời gian đánh giá). Blue/green = clone environment + Swap environment URLs (đổi CNAME).
  • Enhanced health reporting: trạng thái Ok / Warning / Degraded / Severe, nguyên nhân (CPU, 5xx, deploy lỗi). Log: request logs (last 100 lines / full), stream log về CloudWatch Logs.
  • Managed platform updates: tự cập nhật nền tảng trong maintenance window.
  • Lỗi deploy hay gặp: health check URL sai, ứng dụng không nghe đúng cổng, thiếu quyền của instance profile / service role, hết dung lượng.

#CodeDeploy chi tiết

Nền tảngCách triển khaiCấu hình có sẵn
EC2 / on-premisesIn-place (từng nhóm máy) hoặc blue/green (ASG mới, chuyển ALB)AllAtOnce, HalfAtATime, OneAtATime
LambdaChuyển traffic của alias giữa 2 versionCanary10Percent5Minutes, Linear10PercentEvery1Minute, AllAtOnce
ECSBlue/green qua 2 target group của ALB / NLB (hoặc native ECS blue/green)Canary, Linear, AllAtOnce
  • EC2 cần CodeDeploy agent (cài qua SSM) và instance profile đọc được bundle trên S3; deployment group chọn máy theo tag hoặc ASG.
  • appspec.yml: files (chép file), hooks: ApplicationStop → DownloadBundle → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService. Lambda / ECS có hook BeforeAllowTraffic, AfterAllowTraffic.
  • Rollback tự động khi deploy lỗi hoặc khi CloudWatch alarm kêu. Rollback thực chất là deploy lại bản cũ thành một deployment mới.
  • Lỗi hay gặp: agent không chạy, thiếu quyền S3, script trong hook trả mã lỗi hoặc quá thời gian, health check ALB không qua trong blue/green.

#Container và serverless ở góc vận hành

ECS

  • Launch type: Fargate (không quản lý máy) hoặc EC2 (cluster của bạn, ECS agent). Capacity provider kết hợp ASG với managed scaling.
  • Task role (quyền của ứng dụng) khác task execution role (kéo image, đọc secret, ghi log).
  • Service auto scaling theo CPU / RAM / request count / SQS. Deployment circuit breaker tự rollback khi task mới không khoẻ. minimumHealthyPercent / maximumPercent cho rolling update.
  • Task dừng ngay: xem stopped reason (OOM do memory limit, image không kéo được, health check container lỗi, essential container thoát).
  • ECS Exec (dùng SSM) để vào container gỡ lỗi.

EKS

  • Node: managed node group, Fargate profile, Karpenter / Cluster Autoscaler, EKS Auto Mode (AWS quản lý node).
  • Nâng cấp phiên bản: control plane trước, rồi add-on và node; có upgrade insights báo API sắp bị gỡ.
  • Quan sát: control plane logging, Container Insights, Managed Prometheus / Grafana.
  • Pod không lên: thiếu IP trong subnet (VPC CNI dùng IP của VPC), image pull lỗi, thiếu tài nguyên node, IAM (Pod Identity / IRSA).

Lambda

  • Throttles: chạm concurrency của account (mặc định 1.000 / Region) hoặc reserved concurrency của hàm. Provisioned concurrency chống cold start (có thể scale theo lịch bằng Application Auto Scaling).
  • Async invoke lỗi: retry 2 lần, gửi tới DLQ hoặc on-failure destination. Event source mapping (SQS, Kinesis): batch size, partial batch response, bisect batch, maximum retry, IteratorAge.
  • Lambda trong VPC cần NAT / endpoint để gọi dịch vụ AWS; timeout do không ra được mạng là lỗi kinh điển.
  • Version + alias, deploy an toàn qua CodeDeploy / SAM.

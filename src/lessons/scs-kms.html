Các loại key

LoạiAi quản lýGhi nhớ
AWS owned keyAWS, dùng chung nhiều khách hàngKhông thấy, không kiểm soát, miễn phí
AWS managed key (aws/s3, aws/ebs...)AWS tạo trong account bạnKhông sửa key policy, không chia sẻ cross-account được, tự xoay vòng hằng năm
Customer managed keyBạnTự viết key policy, grant, bật / tắt, xoay vòng (tự động 90 đến 2560 ngày, hoặc on-demand), chia sẻ cross-account, xoá sau 7 đến 30 ngày chờ
  • Symmetric (AES-256, mặc định, dùng cho gần như mọi dịch vụ) và asymmetric (RSA / ECC để ký hoặc mã hoá ngoài AWS, tải được public key), HMAC.
  • Multi-Region key: cùng key material ở nhiều Region (primary + replica), giải mã ở Region khác không cần gọi về Region gốc. Dùng cho DynamoDB Global Tables, DR, mã hoá phía client.
  • Imported key material (BYOK): bạn tự tạo key material và nhập vào. Bạn chịu trách nhiệm độ bền, có thể đặt thời hạn hết hạn, xoá ngay lập tức. Không tự xoay vòng được.
  • Custom key store: key nằm trong CloudHSM của bạn, hoặc external key store (XKS) ở ngoài AWS.

Envelope encryption

[go] Ứng dụng / gọi GenerateDataKey -> [q] KMS / trả data key dạng plaintext + bản mã hoá -> [go] Ứng dụng / mã hoá dữ liệu bằng plaintext key, xoá key khỏi bộ nhớ, lưu bản mã hoá của key cạnh dữ liệu -> giải mã sau [q] KMS Decrypt / giải mã data key, rồi giải mã dữ liệu tại chỗ

Dịch vụ như S3, EBS, RDS làm việc này tự động. Tự mã hoá phía client: dùng AWS Encryption SDK.

Key policy: phần quan trọng nhất

  • Mỗi KMS key bắt buộc có key policy. Không như các tài nguyên khác, IAM policy chỉ có tác dụng khi key policy có câu cho phép account root:
{
  "Sid": "Enable IAM policies",
  "Effect": "Allow",
  "Principal": { "AWS": "arn:aws:iam::111122223333:root" },
  "Action": "kms:*",
  "Resource": "*"
}
  • Thiếu câu này thì dù IAM policy cho phép, user vẫn không dùng được key. Xoá nhầm và không ai còn quyền → phải liên hệ AWS Support.
  • Tách vai trò: key administrator (quản lý key, không mã hoá / giải mã được) và key user (dùng key, không sửa policy).
  • Cross-account: key policy cho phép account kia và IAM policy ở account kia cho phép user của họ.
  • Điều kiện hay dùng: kms:ViaService (chỉ dùng key thông qua một dịch vụ, ví dụ s3.ap-southeast-1.amazonaws.com), kms:CallerAccount, kms:EncryptionContext:*.
  • Grant: cấp quyền dùng key tạm thời, có thể thu hồi, hay được dịch vụ AWS dùng (EBS, RDS tạo grant khi gắn volume).
  • Encryption context: cặp key-value đi kèm khi mã hoá, phải khớp khi giải mã. Ghi vào CloudTrail, dùng để kiểm toán và làm điều kiện trong policy.

Xử lý sự cố KMS

LỗiNguyên nhân

ThrottlingExceptionVượt quota request KMS. Dùng S3 Bucket Key, cache data key (Encryption SDK), xin tăng quota

Sợ xoá nhầm key: tạo CloudWatch alarm / EventBridge rule trên CloudTrail event ScheduleKeyDeletion, và dùng SCP cấm kms:ScheduleKeyDeletion trừ role quản trị. Thử trước bằng cách disable key thay vì xoá.

CloudHSM

  • HSM chuyên dụng một khách hàng (single-tenant), chuẩn FIPS 140-3 level 3, bạn toàn quyền quản lý key, AWS không truy cập được key.
  • Dùng khi: cần kiểm soát độc quyền, giao thức chuẩn (PKCS#11, JCE, CNG), SSL/TLS offload cho web server, Oracle TDE, ký code, CA riêng.
  • Bạn tự lo high availability: cluster ít nhất 2 HSM ở 2 AZ.
  • KMS cũng đạt FIPS 140-3 level 3 hiện nay; chọn CloudHSM khi đề nhấn mạnh "single-tenant", "customer exclusive control", "PKCS#11".

Transit Gateway chi tiết

  • Attachment: VPC (chọn một subnet mỗi AZ), VPN, Direct Connect Gateway, TGW peering, Connect (SD-WAN).
  • TGW route table: association (attachment dùng route table nào để tra) và propagation (attachment tự học route vào route table nào). Dùng nhiều route table để cô lập (dev không tới prod nhưng cả hai tới shared services).
  • Ở VPC vẫn phải thêm route trỏ dải đích → TGW.
  • Appliance mode: bật cho VPC chứa firewall để traffic hai chiều đi cùng một AZ (tránh định tuyến bất đối xứng).
  • TGW Flow Logs, TGW Network Manager để quan sát; tối đa 50 Gbps mỗi attachment VPC.
  • Lỗi hay gặp: thiếu route ở route table của VPC, sai association / propagation, SG / NACL, quên subnet attachment ở AZ của instance.

Site-to-Site VPN

  • Thành phần: customer gateway (thiết bị phía bạn), virtual private gateway (gắn một VPC) hoặc Transit Gateway. Mỗi kết nối có 2 tunnel ở 2 thiết bị AWS khác nhau để dự phòng.
  • Định tuyến tĩnh hoặc BGP (dynamic). Bật route propagation trên route table của VPC để tự học route từ VGW.
  • Tunnel down: kiểm tra cấu hình IKE / IPsec phía khách hàng, dead peer detection, NAT-T, IP public của customer gateway, giới hạn băng thông. Metric TunnelState; nhật ký VPN gửi CloudWatch Logs.
  • Accelerated VPN (chỉ với TGW) đi qua Global Accelerator.
  • VPN CloudHub: nhiều văn phòng nối với nhau qua một VGW.

Direct Connect

  • Virtual interface (VIF): private VIF (vào VPC qua VGW / DX Gateway), public VIF (tới dịch vụ AWS public như S3 bằng IP public), transit VIF (tới TGW qua DX Gateway).
  • Direct Connect Gateway: một kết nối DX tới VPC ở nhiều Region / account.
  • Dự phòng: 2 kết nối DX ở 2 location khác nhau (maximum resiliency), hoặc DX + VPN backup (BGP ưu tiên DX qua AS path / local preference).
  • LAG gộp nhiều kết nối. MACsec mã hoá lớp 2 trên kết nối dedicated tốc độ cao. SiteLink nối các DX location với nhau.
  • BGP down: kiểm tra VLAN, ASN, MD5 key, IP peering; metric ConnectionState, ConnectionBpsEgress.

Client VPN

Người dùng từ laptop (OpenVPN client) vào VPC; xác thực bằng chứng chỉ (mutual), Active Directory hoặc SAML; authorization rule theo nhóm; split tunnel để chỉ traffic tới AWS đi qua VPN.

  • Resolver mặc định ở VPC CIDR + 2 (ví dụ 10.0.0.2) hoặc 169.254.169.253.
  • Inbound endpoint: ENI (ít nhất 2 AZ) nhận truy vấn từ on-premises. DNS on-premises đặt conditional forwarder tới IP của endpoint.
  • Outbound endpoint + forwarding rule (tên miền → IP DNS on-premises). Rule system để loại trừ tên miền con. Chia sẻ rule cho account khác bằng RAM, mỗi VPC phải được associate với rule.
  • SG của endpoint cho phép UDP / TCP 53.
  • Resolver query logging: ghi mọi truy vấn DNS từ VPC về CloudWatch Logs / S3 / Firehose.
  • DNS Firewall: rule group chặn / cảnh báo tên miền (danh sách tự tạo hoặc managed list của AWS: malware, botnet), fail open / fail closed.
  • Private hosted zone trùng tên với public zone: trong VPC đã liên kết, private zone thắng (split-horizon DNS).

Bức tranh tổng thể

CloudWatch là "trung tâm quan sát" của AWS, gồm nhiều mảnh. Bài này học metrics và alarms. Bài sau học logs và tracing.

[go] Nguồn metric / dịch vụ AWS, CloudWatch agent, PutMetricData, EMF trong log -> [cache] CloudWatch Metrics / namespace + tên + dimensions -> đánh giá mỗi period [warn] Alarm / OK · ALARM · INSUFFICIENT_DATA -> [q] Hành động / SNS, EC2 action, Auto Scaling, SSM, EventBridge

Khái niệm cốt lõi của metric

Khái niệmGiải thíchVí dụ
NamespaceNhóm chứa metric. Dịch vụ AWS dùng tiền tố AWS/AWS/EC2, AWS/ApplicationELB, CWAgent, MyApp
Metric nameTên con số được đoCPUUtilization
DimensionCặp tên = giá trị để phân biệt các chuỗi số liệu. Tối đa 30 dimension mỗi metricInstanceId=i-0abc, AutoScalingGroupName=web
StatisticCách gộp các điểm dữ liệu trong một periodAverage, Sum, Minimum, Maximum, SampleCount, percentile (p50, p90, p99), trimmed mean (TM99)
PeriodKhoảng thời gian gộp1, 5, 10, 30 giây (high-resolution), hoặc bội số 60 giây
UnitĐơn vịPercent, Bytes, Count, Seconds

Metric là duy nhất theo namespace + tên + toàn bộ dimensions. Gửi metric với dimension InstanceId mà alarm lại tạo với dimension InstanceId + InstanceType là hai metric khác nhau, alarm sẽ nằm ở INSUFFICIENT_DATA mãi. Đây là nguyên nhân số một của "alarm không chạy" trong đề.

Thời gian lưu dữ liệu

Độ phân giải điểm dữ liệuGiữ trong
Dưới 60 giây (high-resolution)3 giờ
60 giây15 ngày
5 phút63 ngày

Dữ liệu cũ tự được gộp lên độ phân giải thô hơn. Metric không xoá được bằng tay, không còn dữ liệu mới thì tự biến mất sau 15 tháng. Muốn giữ lâu hơn: Metric Streams đẩy sang Firehose → S3, hoặc dùng công cụ bên thứ ba.

Gửi metric tuỳ chỉnh

  • aws cloudwatch put-metric-data / API PutMetricData: tối đa 1.000 metric mỗi request. Có thể gửi điểm dữ liệu có timestamp tới 2 tuần trong quá khứ và 2 giờ trong tương lai.
  • StorageResolution=1: high-resolution (1 giây). Mặc định 60 là standard.
  • Embedded Metric Format (EMF): ghi một dòng log JSON có cấu trúc đặc biệt, CloudWatch tự trích ra metric. Rất tiện cho Lambda: không cần gọi API, không làm chậm hàm.
  • Metric Streams: đẩy metric gần thời gian thực ra Firehose (tới S3, Datadog, New Relic, Splunk...).

CloudWatch agent chi tiết

Agent hợp nhất (unified CloudWatch agent) thu cả metric và log, chạy trên Linux, Windows, macOS, EC2 và máy on-premises.

Các bước triển khai chuẩn

  1. Quyền: gắn instance profile có CloudWatchAgentServerPolicy (và AmazonSSMManagedInstanceCore để quản lý bằng SSM). Role dùng để ghi cấu hình lên Parameter Store cần thêm CloudWatchAgentAdminPolicy.
  2. Cài đặt: SSM Run Command chạy document AWS-ConfigureAWSPackage với package AmazonCloudWatchAgent cho mọi máy theo tag.
  3. Tạo cấu hình: chạy wizard amazon-cloudwatch-agent-config-wizard trên một máy mẫu, lưu file JSON lên Parameter Store (tên thường bắt đầu AmazonCloudWatch-).
  4. Khởi động: Run Command AmazonCloudWatch-ManageAgent với action configure, nguồn cấu hình là tên parameter.
  5. Duy trì: State Manager association để máy mới tự cài và cấu hình.
{
  "agent": { "metrics_collection_interval": 60 },
  "metrics": {
    "namespace": "CWAgent",
    "append_dimensions": { "InstanceId": "${aws:InstanceId}", "AutoScalingGroupName": "${aws:AutoScalingGroupName}" },
    "aggregation_dimensions": [["AutoScalingGroupName"]],
    "metrics_collected": {
      "mem":  { "measurement": ["mem_used_percent"] },
      "disk": { "measurement": ["used_percent"], "resources": ["/"] },
      "procstat": [{ "exe": "nginx", "measurement": ["pid_count"] }]
    }
  },
  "logs": {
    "logs_collected": {
      "files": { "collect_list": [{
        "file_path": "/var/log/app/app.log",
        "log_group_name": "/app/web",
        "log_stream_name": "{instance_id}",
        "retention_in_days": 90
      }] }
    }
  }
}
  • aggregation_dimensions theo AutoScalingGroupName: có metric RAM tổng hợp cho cả ASG, dùng được cho target tracking theo bộ nhớ.
  • procstat: theo dõi process (process có đang chạy không, CPU / RAM của nó). Alarm khi pid_count = 0 là cách phát hiện dịch vụ chết.
  • Windows: thu Performance Counters và Windows Event Log.
  • On-premises: agent cần credential, dùng file profile AmazonCloudWatchAgent hoặc đăng ký máy với SSM bằng hybrid activation.
  • File log của agent: /opt/aws/amazon-cloudwatch-agent/logs/amazon-cloudwatch-agent.log để gỡ lỗi.

Đề hay hỏi: "Metric bộ nhớ có trong CloudWatch nhưng không có dimension AutoScalingGroupName nên không làm alarm cho cả nhóm được". Cách sửa: thêm append_dimensions / aggregation_dimensions trong cấu hình agent.

Agent không gửi dữ liệu: checklist

  1. Agent có đang chạy (amazon-cloudwatch-agent-ctl -a status).
  2. Role có cloudwatch:PutMetricData, logs:PutLogEvents, logs:CreateLogStream.
  3. Có đường mạng: Internet / NAT, hoặc interface endpoint monitoring và logs.
  4. Đường dẫn file log đúng, agent có quyền đọc file.
  5. Xem đúng namespace (CWAgent mặc định) và đúng Region.

Tham sốÝ nghĩa

Statistic + periodVí dụ Average trong 5 phút
ThresholdNgưỡng tĩnh, hoặc anomaly detection band

Hành động của alarm

  • SNS: email, SMS, Lambda, SQS, HTTPS, Chatbot.
  • EC2 actions: stop, terminate, reboot, recover. Cần role liên kết dịch vụ (tự tạo). Recover chỉ cho StatusCheckFailed_System.
  • Auto Scaling: kích hoạt step / simple scaling policy.
  • Systems Manager: tạo OpsItem trong OpsCenter, hoặc tạo incident trong Incident Manager.
  • Lambda trực tiếp (alarm action gọi Lambda).
  • Mọi thay đổi trạng thái đều là event CloudWatch Alarm State Change trong EventBridge, nên gọi được bất kỳ target nào (SSM Automation, Step Functions...).

Composite alarm

ALARM("cpu-cao") AND ALARM("loi-5xx-cao") AND NOT ALARM("dang-bao-tri")
  • Chỉ composite alarm gắn hành động thông báo, các alarm con không gửi gì: giảm "bão" cảnh báo.
  • Action suppression: tạm chặn hành động của composite alarm khi một alarm khác (ví dụ "đang deploy") ở trạng thái ALARM, có wait / extension period.
  • Composite alarm không gắn được EC2 action hay Auto Scaling action, chỉ SNS / SSM / Lambda.

Anomaly detection và metric math

  • Anomaly detection: CloudWatch học 2 tuần dữ liệu, dựng dải giá trị bình thường theo giờ / ngày trong tuần. Alarm khi metric ra ngoài dải (trên, dưới, hoặc cả hai). Điều chỉnh độ rộng dải bằng hệ số; loại trừ khoảng thời gian bất thường khỏi dữ liệu huấn luyện.
  • Metric math: m1/m2*100, SUM(METRICS()), FILL(m1, 0), RATE(), IF(). Dùng để tính tỉ lệ lỗi, tổng nhiều metric, điền dữ liệu thiếu.
  • Metrics Insights: SELECT AVG(CPUUtilization) FROM SCHEMA("AWS/EC2", InstanceId) GROUP BY InstanceId ORDER BY AVG() DESC LIMIT 10. Một alarm Metrics Insights theo dõi được cả đội máy, máy mới tự được tính.

Dashboards

  • Dashboard là tài nguyên global, một dashboard hiện metric nhiều Region.
  • Widget: line, stacked area, number, gauge, bar, pie, text (Markdown), log table (Logs Insights), alarm status, custom widget (Lambda trả HTML).
  • Automatic dashboards cho từng dịch vụ có sẵn.
  • Tạo bằng CloudFormation (AWS::CloudWatch::Dashboard) hoặc API PutDashboard để chuẩn hoá cho mọi môi trường.
  • Chia sẻ: công khai (ai có link xem được), cho danh sách email (qua Cognito), hoặc qua SSO. Hoặc dùng cross-account observability.

Cross-account observability

[go] Source account A, B, C... / chia sẻ metric, log, trace -> liên kết qua Observability Access Manager (sink / link) [cache] Monitoring account / dashboard, alarm, Logs Insights trên dữ liệu của mọi account

Dùng với Organizations để tự liên kết account mới (CloudFormation StackSets hoặc chính sách của OAM). Cách cũ hơn: cross-account cross-Region dashboard bằng role CloudWatch-CrossAccountSharingRole.

EC2 auto recovery và status check

  • Simplified automatic recovery: nhiều loại instance (không có instance store, tenancy default / dedicated) tự recover khi system status check lỗi mà không cần alarm.
  • Muốn tự làm: alarm StatusCheckFailed_System (Maximum, 1 phút, 2 datapoints) với action arn:aws:automate:region:ec2:recover.
  • Recover giữ: instance ID, private IP, Elastic IP, metadata, placement group, EBS. Mất: dữ liệu trong RAM, public IP động (nếu không có EIP) được giữ trong một số trường hợp nhưng đừng trông cậy.
  • StatusCheckFailed_Instance: dùng action reboot.

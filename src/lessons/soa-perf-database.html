RDS: cấu hình và vận hành

  • Parameter group: cấu hình engine. Parameter dynamic áp ngay (hoặc theo apply immediately); static cần reboot. Trạng thái pending-reboot cho biết còn chờ reboot. Default parameter group không sửa được: tạo custom rồi gán.
  • Option group: tính năng thêm (Oracle TDE, SQL Server native backup...).
  • Maintenance window: AWS vá engine / OS; Multi-AZ thì vá standby trước rồi failover để giảm gián đoạn.
  • Sửa cấu hình (đổi instance class, storage): chọn apply immediately hoặc đợi maintenance window. Đổi class có gián đoạn (Multi-AZ giảm xuống còn thời gian failover).
  • Storage autoscaling: tự tăng khi còn dưới 10% trống trong 5 phút; đặt maximum storage threshold.
  • Storage: gp3 (IOPS / throughput chỉnh riêng), io1 / io2 (Provisioned IOPS). Sau khi tăng storage phải chờ 6 giờ mới sửa tiếp.
  • Kết nối không được: SG của RDS chưa cho SG của app ở cổng 3306 / 5432; RDS không public mà client ở ngoài; sai subnet group; hết max_connections (phụ thuộc RAM của instance class).

RDS Proxy

  • Pool và tái sử dụng kết nối: hàng nghìn kết nối từ ứng dụng (đặc biệt Lambda) dồn vào ít kết nối tới database.
  • Giảm thời gian failover tới 66%: proxy giữ kết nối của ứng dụng, chuyển sang instance mới.
  • Xác thực: secret trong Secrets Manager, ứng dụng có thể dùng IAM authentication tới proxy; có thể bắt buộc TLS.
  • Chỉ truy cập từ trong VPC. Có read-only endpoint cho Aurora replica.
  • "Pinning": một số thao tác (biến phiên, prepared statement kiểu cũ) ghim kết nối, làm giảm hiệu quả gộp.

Aurora

  • Storage dùng chung tự mở rộng tới 128 TiB (256 TiB bản mới), 6 bản sao trên 3 AZ, tự chữa lỗi.
  • Tối đa 15 Aurora Replica, failover thường dưới 30 giây theo failover priority tier (0 cao nhất).
  • Endpoint: cluster (writer), reader (cân tải các replica), custom endpoint (nhóm replica riêng cho báo cáo), instance endpoint.
  • Aurora Auto Scaling: thêm / bớt replica theo CPU hoặc số kết nối.
  • Aurora Serverless v2: tự co giãn ACU theo tải trong vài giây, có thể giảm về 0 khi rảnh.
  • Global Database: Region phụ chỉ đọc, độ trễ sao chép dưới 1 giây; managed switchover / failover sang Region phụ (RTO khoảng 1 phút). Write forwarding cho phép ghi từ Region phụ.
  • Backtrack (Aurora MySQL): quay ngược cluster về thời điểm trước (tối đa 72 giờ) tại chỗ, không restore. Cloning: tạo cluster mới dùng chung storage (copy-on-write), nhanh và rẻ cho test.
  • Aurora I/O-Optimized: không tính phí I/O, hợp khi I/O chiếm trên 25% chi phí.

DynamoDB

  • On-demand (trả theo request, tự co giãn) vs provisioned (đặt RCU / WCU, có auto scaling theo target utilization). Đổi mode mỗi 24 giờ một lần.
  • 1 RCU = 1 lần đọc strongly consistent / giây hoặc 2 eventually consistent, item tới 4 KB. 1 WCU = 1 lần ghi / giây, item tới 1 KB. Transaction gấp đôi.
  • Throttling (ProvisionedThroughputExceededException): capacity thấp, hot partition (một partition key nhận quá nhiều request; mỗi partition tối đa 3.000 RCU / 1.000 WCU), GSI bị throttle làm throttle cả bảng chính. SDK tự retry với backoff.
  • DAX: cache trong bộ nhớ cho đọc lặp lại, độ trễ micro giây, tương thích API (đổi endpoint). Không giúp ghi.
  • Global Tables: multi-Region, multi-active. PITR 35 ngày. TTL tự xoá item hết hạn (không tốn WCU). Streams + Lambda cho xử lý thay đổi.
  • Metric: ConsumedReadCapacityUnits, ThrottledRequests, ReadThrottleEvents, SystemErrors; CloudWatch Contributor Insights for DynamoDB tìm partition key nóng.

ElastiCache

  • Engine: Valkey / Redis OSS (cấu trúc dữ liệu phong phú, replication, Multi-AZ auto failover, backup, cluster mode chia shard) và Memcached (đơn giản, đa luồng, không replication / backup).
  • ElastiCache Serverless: không cần chọn node, tự co giãn.
  • Metric: CPUUtilization / EngineCPUUtilization (Redis đơn luồng: xem EngineCPU), Evictions (thiếu RAM), CurrConnections, CacheHitRate, ReplicationLag, DatabaseMemoryUsagePercentage.
  • Mở rộng: scale up (node lớn hơn), scale out (thêm replica để đọc, thêm shard để ghi / tăng bộ nhớ trong cluster mode).
  • Chiến lược cache: lazy loading (cache-aside), write-through, đặt TTL.

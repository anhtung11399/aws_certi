Hai máy không nói chuyện được: kiểm tra theo thứ tự

[go] EC2 / security group (stateful) -> [q] Subnet / NACL (stateless, chiều đi và chiều về) -> [cache] Route table / 0.0.0.0/0 → NAT GW -> [ok] NAT Gateway / nằm ở public subnet -> [ext] Internet Gateway / route table của public subnet
LớpKiểm tra
Security groupStateful: cho vào thì chiều về tự được phép. Chỉ có Allow. Nguồn có thể là một security group khác
NACLStateless: phải cho phép cả chiều về, gồm ephemeral ports 1024-65535. Có Allow và Deny, xét theo số thứ tự rule từ nhỏ đến lớn
Route tableSubnet có route tới đích không: IGW (public), NAT (private ra Internet), peering, TGW, VGW, endpoint
Public IPInstance ở public subnet cần public IP / Elastic IP để ra Internet qua IGW
NAT GatewayPhải đặt ở public subnet, có Elastic IP. Lỗi ErrorPortAllocation: quá nhiều kết nối đồng thời tới cùng một đích, thêm IP phụ cho NAT
OS firewalliptables / Windows Firewall bên trong máy

Công cụ

  • VPC Flow Logs (VPC, subnet, ENI): ghi ACCEPT / REJECT cho từng luồng. Gửi về CloudWatch Logs hoặc S3. Thấy chiều vào ACCEPT mà chiều ra REJECT → thường là NACL chặn ephemeral port (vì SG stateful không chặn chiều về). Flow Logs không ghi nội dung gói tin, không ghi traffic tới DNS của Amazon, metadata 169.254.169.254.
  • Reachability Analyzer: kiểm tra cấu hình xem từ A tới B có đường đi không, chỉ ra thành phần chặn (SG, NACL, route), không cần gửi gói tin thật.
  • Network Access Analyzer: tìm các đường truy cập ngoài ý muốn (ví dụ mạng nào đi được tới database từ Internet).
  • Traffic Mirroring: sao chép gói tin thật để phân tích sâu (IDS).

DNS: Route 53 Resolver

  • Mỗi VPC có DNS resolver ở địa chỉ .2 của dải VPC (ví dụ 10.0.0.2).
  • Private hosted zone: tên miền nội bộ, gắn với VPC. Cần bật enableDnsHostnames và enableDnsSupport.
  • Inbound endpoint: máy on-premises hỏi được tên miền private của AWS.
  • Outbound endpoint + forwarding rule: máy trong VPC hỏi được tên miền của on-premises (ví dụ corp.local). Chia sẻ rule cho VPC khác bằng RAM.
  • Resolver query logs: ghi mọi truy vấn DNS từ VPC. DNS Firewall: chặn tên miền độc hại.

"Máy on-premises cần phân giải tên trong private hosted zone" → inbound endpoint. "EC2 cần phân giải tên miền của data center" → outbound endpoint + forwarding rule. Hai chiều rất hay bị đảo trong đáp án.

- Security group chặn chiều về + NACL của subnet chưa cho phép chiều vào trên ephemeral ports 1024-65535 - NAT Gateway thiếu Elastic IP ? SG stateful tự cho chiều về. NACL stateless phải mở dải cổng tạm cho response quay về. - Inbound Resolver endpoint + Outbound Resolver endpoint và forwarding rule cho corp.internal tới IP DNS on-premises - Private hosted zone corp.internal ? Truy vấn đi từ VPC ra ngoài cần outbound endpoint và rule chuyển tiếp.

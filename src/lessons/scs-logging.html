  • Organization trail: tạo ở management account (hoặc delegated admin), tự áp cho mọi account, account con không sửa / xoá được.
  • Trail multi-Region (mặc định khi tạo ở console) để không sót Region nào. Bật global service events.
  • Log file integrity validation: tạo file digest (SHA-256, ký số) mỗi giờ để chứng minh log không bị sửa / xoá. Kiểm bằng aws cloudtrail validate-logs.
  • Gửi trail sang CloudWatch Logs để làm metric filter và alarm.
  • CloudTrail Lake: lưu event và truy vấn bằng SQL ngay trong CloudTrail (tới 10 năm), gom được event bên ngoài AWS. Thay cho tự dựng S3 + Athena.
  • Log tới S3 chậm khoảng 5 đến 15 phút, không phải thời gian thực.

CloudTrail chi tiết thêm

  • Advanced event selectors: lọc theo eventCategory, resources.type, resources.ARN, eventName, readOnly... để chỉ ghi data event cần thiết.
  • Mã hoá log bằng SSE-KMS: key policy cho cloudtrail.amazonaws.com với điều kiện aws:SourceArn của trail và encryption context; người đọc log cần kms:Decrypt.
  • SNS notification khi có file log mới (cho hệ thống bên ngoài kéo về).
  • Organization trail: tạo ở management account hoặc delegated administrator của CloudTrail; thành viên thấy trail nhưng không sửa / xoá được.
  • CloudTrail Lake: event data store (giữ tới 10 năm hoặc theo gói), truy vấn SQL, federation sang Athena, nạp event từ ngoài AWS (integration), dashboard; có thể lưu cả Config configuration items.
  • Network activity events: API call đi qua VPC endpoint, phát hiện ai dùng endpoint để truy cập tài nguyên ngoài tổ chức.
  • Kiểm tra toàn vẹn: digest file mỗi giờ ký bằng private key của CloudTrail, tham chiếu digest trước đó (chuỗi). aws cloudtrail validate-logs --trail-arn ... --start-time ... báo file bị sửa / xoá.

Account CloudWatch Logs tập trung

  • Cách 1: cross-account observability (OAM): log nằm ở account nguồn, account giám sát truy vấn được bằng Logs Insights.
  • Cách 2: subscription filter từng log group (hoặc account-level subscription filter) gửi tới destination (Kinesis / Firehose) ở account log trung tâm; destination policy cho phép các account nguồn (hoặc cả Organization).
  • Cách 3: log centralization của CloudWatch (sao chép log group về account / Region trung tâm theo rule của Organization).
  • Bảo vệ log: retention, KMS, data protection policy (che dữ liệu nhạy cảm), resource policy hạn chế ai xoá log group.

Phân tích log

  • Athena: truy vấn SQL trực tiếp trên log trong S3 (CloudTrail, Flow Logs, ALB, WAF). Dùng partition projection để rẻ và nhanh.
  • CloudWatch Logs Insights: truy vấn log trong CloudWatch Logs.
  • OpenSearch Service: tìm kiếm, tương quan, dashboard cho log lớn, SIEM tự dựng. Đẩy log qua subscription filter → Firehose / Lambda.
  • Lambda: parse, chuẩn hoá, làm giàu log. Managed Grafana: dashboard.
SELECT useridentity.arn, eventsource, eventname, count(*) AS n
FROM cloudtrail_logs
WHERE errorcode IN ('AccessDenied', 'Client.UnauthorizedOperation')
  AND eventtime > to_iso8601(current_timestamp - interval '1' day)
GROUP BY 1, 2, 3
ORDER BY n DESC
LIMIT 20;

filter action = "REJECT"
| stats count(*) as rejects by srcAddr, dstPort
| sort rejects desc
| limit 20
  • Tương quan nhiều nguồn: dùng chung khoá như IP, instance ID, access key ID, request ID, trace ID; Security Lake (OCSF) giúp các nguồn có cùng lược đồ để JOIN.
  • OpenSearch Service: SIEM tự dựng, Security Analytics (rule Sigma có sẵn, phát hiện mối đe doạ trên log), alerting, dashboard; nạp qua Firehose / OpenSearch Ingestion.
  • Managed Grafana: dashboard từ CloudWatch, OpenSearch, Athena.

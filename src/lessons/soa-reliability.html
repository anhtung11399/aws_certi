Elastic Load Balancing: xử lý sự cố

Health check

  • Target group định nghĩa: protocol, port, path (ví dụ /health), mã thành công (mặc định 200), healthy / unhealthy threshold, interval, timeout.
  • Target unhealthy hay gặp vì: security group của target không cho phép security group của ALB vào cổng ứng dụng; path health check trả 301 / 302 / 404; ứng dụng khởi động chậm hơn interval × threshold; NACL chặn cổng.
  • Tất cả target đều unhealthy: ALB vẫn gửi request tới mọi target (fail open).
  • Deregistration delay (connection draining, mặc định 300 giây): khi rút target, ALB chờ request đang chạy xong. Ứng dụng request ngắn thì giảm xuống để deploy nhanh hơn.
  • Slow start: cho target mới nhận tải tăng dần.

Mã lỗi ALB

MãThường do
502 Bad GatewayTarget đóng kết nối, trả response sai định dạng, hoặc keep-alive timeout của ứng dụng ngắn hơn idle timeout của ALB (mặc định 60 giây). Lambda target trả response sai cấu trúc
503 Service UnavailableTarget group không có target nào được đăng ký, hoặc không có target khoẻ trong AZ được bật (khi tắt cross-zone)
504 Gateway TimeoutTarget không trả lời trong idle timeout (ứng dụng chậm, database chậm), hoặc không kết nối được target
460Client đóng kết nối trước khi ALB kịp trả lời
4xx từ targetLỗi của ứng dụng, xem metric HTTPCode_Target_4XX_Count để phân biệt với lỗi của ALB (HTTPCode_ELB_5XX_Count)
  • Bật access logs của ALB (về S3) để xem từng request: thời gian xử lý, mã lỗi, target nào. Phân tích bằng Athena.
  • SurgeQueueLength, SpilloverCount (Classic LB): target không kịp nhận, request bị bỏ.
  • Sticky session làm tải lệch giữa các target. Cross-zone load balancing: ALB luôn bật, NLB mặc định tắt (bật thì có phí chuyển dữ liệu giữa AZ).
  • NLB giữ IP nguồn của client, có IP tĩnh mỗi AZ (gắn Elastic IP được). ALB thì IP thay đổi, lấy IP client từ header X-Forwarded-For.

ALB báo 502 ngắt quãng, ứng dụng Node.js / Nginx phía sau dùng keep-alive timeout mặc định 5 giây trong khi ALB idle timeout 60 giây: ALB gửi request vào một kết nối mà backend vừa đóng. Cách sửa: tăng keep-alive timeout của backend lên lớn hơn idle timeout của ALB.

Thiết kế sống sót khi mất một AZ

  • ASG trải trên ít nhất 2 AZ (tốt nhất 3), đủ máy để khi mất một AZ các AZ còn lại gánh được (static stability: chạy dư sẵn thay vì chờ scale).
  • RDS Multi-AZ, ElastiCache Multi-AZ có automatic failover, EFS (Regional), S3.
  • NAT Gateway đặt mỗi AZ một cái, route table của private subnet trỏ tới NAT cùng AZ. Một NAT duy nhất là điểm lỗi đơn.
  • Route 53 Application Recovery Controller (zonal shift): chuyển traffic khỏi một AZ đang có vấn đề.

Route 53

Routing policyDùng khi
SimpleMột tài nguyên, không health check
FailoverActive-passive: primary có health check, hỏng thì trả secondary (thường là trang tĩnh trên S3 / Region DR)
WeightedChia tỉ lệ traffic: canary 10% cho bản mới, A/B test
LatencyTrả về Region có độ trễ thấp nhất với người dùng
GeolocationTheo quốc gia / châu lục của người dùng (pháp lý, ngôn ngữ). Nhớ đặt bản ghi Default
GeoproximityTheo khoảng cách, có bias để kéo / đẩy traffic (dùng Traffic Flow)
Multivalue answerTrả tới 8 IP khoẻ, cân tải đơn giản phía client
IP-basedTheo dải IP nguồn (CIDR) của client
  • Health check kiểm tra endpoint (HTTP/HTTPS/TCP, có thể tìm chuỗi trong response), calculated health check (kết hợp nhiều check), hoặc theo trạng thái một CloudWatch alarm (dùng cho tài nguyên private không gọi được từ Internet).
  • Health checker nằm ngoài VPC: firewall / security group phải cho phép dải IP của Route 53 health checker.
  • Alias record: trỏ tới ELB, CloudFront, S3 website, API Gateway, VPC endpoint... Miễn phí truy vấn, dùng được ở zone apex (example.com), CNAME thì không.
  • TTL: hạ TTL trước khi đổi bản ghi để thay đổi lan nhanh.
  • Chuyển tên miền sang Route 53 mà tên miền không phân giải: kiểm tra NS record ở nhà đăng ký có trùng với hosted zone không.

Caching để giảm tải

  • CloudFront trước ALB / S3 (bài 12). ElastiCache trước database. DAX trước DynamoDB. API Gateway có cache theo stage.
  • RDS read replica cho báo cáo, tách tải đọc nặng khỏi primary.

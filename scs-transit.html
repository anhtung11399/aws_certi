Bảo vệ dữ liệu khi truyền

Ép TLS (ELB security policy, aws:SecureTransport, RDS), PrivateLink, VPC endpoint, Client VPN, Verified Access, mã hoá giữa các node (EMR, EKS, SageMaker), Nitro encryption.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Ép buộc mã hoá in transit
  • Truy cập riêng tư không qua Internet

#Ép buộc mã hoá khi kết nối

Tài nguyênCách ép TLS
ALB / NLBListener HTTPS / TLS, security policy (ví dụ ELBSecurityPolicy-TLS13-1-2-2021-06 chỉ TLS 1.2 / 1.3; có biến thể FIPS và post-quantum -PQ-), redirect HTTP → HTTPS, mTLS (ALB: verify với trust store / passthrough)
CloudFrontViewer protocol policy Redirect / HTTPS only, security policy tối thiểu, origin protocol HTTPS only
API GatewayChỉ HTTPS; custom domain chọn TLS policy; mTLS với truststore trên S3; tắt default execute-api endpoint khi dùng custom domain
S3Bucket policy Deny khi aws:SecureTransport = false; điều kiện s3:TlsVersion để yêu cầu TLS 1.2+
RDS / AuroraPostgreSQL / SQL Server: rds.force_ssl = 1; MySQL / MariaDB: require_secure_transport = ON; client dùng CA bundle của RDS (xoay vòng CA định kỳ)
ElastiCache (Valkey / Redis)Bật in-transit encryption lúc tạo (bản mới bật được sau, có chế độ preferred → required), AUTH / RBAC
DynamoDB, mọi API AWSEndpoint chỉ HTTPS; dùng endpoint FIPS khi cần
SNS / SQSPolicy Deny khi aws:SecureTransport = false
EFSMount với tuỳ chọn tls (amazon-efs-utils); file system policy Deny khi không dùng TLS
Chặn mọi request không mã hoá tới queue SQS
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "sqs:*",
  "Resource": "arn:aws:sqs:ap-southeast-1:111122223333:orders",
  "Condition": { "Bool": { "aws:SecureTransport": "false" } }
}

Đáp án "Allow khi SecureTransport = true" không ép buộc được (request HTTP vẫn có thể được Allow bởi policy khác). Mẫu chuẩn luôn là Deny khi SecureTransport = false.

#Truy cập riêng tư, không qua Internet

  • VPC endpoint + endpoint policy; Private DNS để SDK dùng tên mặc định mà vẫn đi qua endpoint.
  • PrivateLink: dịch vụ của bạn cho khách hàng / account khác: endpoint service sau NLB / GWLB, allowlist principal, yêu cầu chấp nhận kết nối, có thể bật Private DNS name đã xác minh.
  • Client VPN: laptop vào VPC, mutual TLS / AD / SAML, authorization rule theo nhóm, split tunnel.
  • Verified Access: không cần VPN, kiểm tra danh tính và thiết bị từng request.
  • Kết nối on-premises: Site-to-Site VPN (IPsec), Direct Connect + MACsec / VPN.

#Mã hoá giữa các thành phần bên trong

Dịch vụCấu hình
Nitro encryptionInstance Nitro hỗ trợ (C5n, M6i, ... nhiều dòng mới) tự mã hoá traffic giữa chúng ở phần cứng (AES-256) khi ở cùng VPC / VPC peering cùng Region, không ảnh hưởng hiệu năng. Kết nối EBS cũng được mã hoá khi volume mã hoá
EMRSecurity configuration: in-transit encryption (TLS giữa các node với chứng chỉ PEM từ S3 hoặc custom provider), at-rest encryption (S3: SSE-S3 / SSE-KMS / CSE-KMS; đĩa local: KMS / LUKS), Kerberos, Lake Formation
EKSPod-to-pod: service mesh (mTLS, ví dụ Istio / App Mesh cũ / VPC Lattice), hoặc dựa vào Nitro encryption; secret Kubernetes mã hoá bằng KMS (envelope encryption)
SageMaker AIInter-container traffic encryption cho training phân tán, VPC mode / network isolation, KMS cho volume và output
OpenSearchNode-to-node encryption, HTTPS bắt buộc (enforce HTTPS)
MSK (Kafka)TLS giữa client - broker và giữa broker

Câu hỏi nhanh. Kiểm toán yêu cầu mọi kết nối tới ALB phải dùng TLS 1.2 trở lên với cipher mạnh. Cấu hình?

Security policy của listener quyết định giao thức và cipher được chấp nhận.

Câu hỏi nhanh. Cụm EMR xử lý dữ liệu y tế cần mã hoá dữ liệu truyền giữa các node. Cấu hình ở đâu?

Security configuration của EMR quản lý mã hoá in transit và at rest cho cụm.

Câu hỏi nhanh. Ứng dụng đối tác ở account khác cần gọi API nội bộ của bạn mà không qua Internet và không cho họ thấy toàn bộ VPC. Giải pháp?

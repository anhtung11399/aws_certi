EC2: chẩn đoán và tối ưu

Instance family, status check, lỗi khởi chạy, placement group, ENA / EFA, burstable, Nitro, Capacity Reservation, Spot, Compute Optimizer, chi phí.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Chẩn đoán EC2 chậm hay lỗi
  • Chọn instance và cấu hình mạng phù hợp
  • Right-size và tối ưu chi phí

#Chọn instance đúng việc

HọVí dụHợp với
General purposeM7i, M7g, M8g, T3, T4gWeb, ứng dụng thông thường. T là burstable
Compute optimizedC7i, C7g, C8gXử lý nặng CPU: batch, encode video, game server
Memory optimizedR7i, R8g, X2, z1dDatabase trong RAM, cache, phân tích
Storage optimizedI4i, I7i, D3, Im4gnIOPS cực cao trên instance store NVMe, data warehouse
AcceleratedP5, G6, Inf2, Trn1ML, đồ hoạ
  • Hậu tố: g = Graviton (ARM, rẻ hơn khoảng 20%, hiệu năng / giá tốt), i = Intel, a = AMD, d = có instance store NVMe, n = mạng cao, e = thêm RAM / storage, flex = linh hoạt giá rẻ.
  • Chuyển sang Graviton: AMI phải là ARM64, phần mềm phải hỗ trợ ARM.
  • Đổi instance type: phải stop (EBS-backed), đổi, rồi start. Instance store mất dữ liệu khi stop.
  • Nitro System: nền tảng phần cứng hiện đại của EC2, cần driver ENA và NVMe trong AMI. Đổi từ dòng cũ (Xen, ví dụ M4) sang dòng Nitro (M5 trở lên) mà máy không khởi động: AMI thiếu driver ENA / NVMe.

#Mạng của EC2

  • Băng thông phụ thuộc kích thước instance ("Up to 10 Gbps" nghĩa là có burst, baseline thấp hơn).
  • Enhanced networking: ENA (tới 100 / 200 Gbps), Intel 82599 VF (cũ). EFA: cho HPC / ML, giao tiếp bỏ qua kernel (OS-bypass), dùng với MPI / NCCL, trong cùng subnet / cluster placement group.
  • Kiểm tra ENA bật: ethtool -i eth0 driver là ena; thuộc tính enaSupport của instance.
  • Metric ENA (qua ethtool -S, agent thu được): bw_in_allowance_exceeded, pps_allowance_exceeded, conntrack_allowance_exceeded cho biết đang bị giới hạn mạng của instance → nâng instance.
  • Jumbo frames (MTU 9001) trong VPC; ra Internet / qua VPN là 1500.

Placement group

LoạiĐặc điểmHợp với
ClusterCùng AZ, gần nhau, độ trễ thấp nhất, 10 Gbps luồng đơnHPC, tính toán liên kết chặt. Rủi ro: cùng hỏng
SpreadMỗi máy một rack riêng, tối đa 7 máy / AZ (rack-level)Vài máy cực quan trọng
PartitionTối đa 7 partition / AZ, mỗi partition một nhóm rack, hàng trăm máy, metadata cho biết partitionHadoop, Cassandra, Kafka

Thêm máy vào cluster placement group bị thiếu capacity: stop hết máy trong group rồi start lại cùng lúc (để AWS tìm chỗ đủ cho cả nhóm), hoặc dùng cùng loại instance và launch một lần.

#Burstable T-family

  • Mỗi kích thước có baseline (ví dụ t3.micro 10%). Dưới baseline thì tích CPU credit, trên baseline thì tiêu credit.
  • Standard mode: hết credit thì bị kìm về baseline (ứng dụng chậm hẳn). Unlimited mode (mặc định của T3 / T4g): được vượt, trả thêm phí nếu trung bình 24 giờ vượt baseline (CPUSurplusCreditsCharged).
  • CPU cao liên tục → không hợp T-family, chuyển M / C.

#Right-sizing

  • Compute Optimizer: phân tích 14 ngày (tới 93 ngày với enhanced infrastructure metrics trả phí), đề xuất EC2, ASG, EBS, Lambda, ECS trên Fargate, RDS, license. Kết quả: Over-provisioned, Under-provisioned, Optimized. Bật cho cả Organization.
  • Có metric RAM từ CloudWatch agent thì đề xuất chính xác hơn.
  • Cost Explorer: rightsizing recommendations, xem chi phí theo dịch vụ / tag / account. Cost Optimization Hub: gom mọi khuyến nghị tiết kiệm.
  • Trusted Advisor: low utilization EC2, idle load balancer, unassociated EIP, underutilized EBS.
  • AWS Budgets: cảnh báo theo chi phí / usage / RI coverage, có budget actions (tự áp SCP / IAM policy, dừng EC2 khi vượt ngân sách).
  • Cost Anomaly Detection: ML phát hiện chi phí tăng bất thường.

#Kiểm tra từ bên trong

  • Instance metadata (IMDSv2): TOKEN=$(curl -X PUT http://169.254.169.254/latest/api/token -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") rồi curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id.
  • User data chỉ chạy lần khởi động đầu (mặc định), log ở /var/log/cloud-init-output.log. Muốn chạy mỗi lần boot phải cấu hình cloud-init.
  • Hibernate: lưu RAM xuống EBS gốc (phải mã hoá, đủ dung lượng), khởi động lại nhanh với trạng thái cũ.

Câu hỏi nhanh. Sau khi đổi instance type từ m4.large sang m6i.large, máy không qua được status check. Nguyên nhân có khả năng nhất?

Dòng Nitro dùng ENA cho mạng và NVMe cho EBS; OS cũ thiếu driver sẽ không khởi động / không có mạng.

Câu hỏi nhanh. Máy chủ không phản hồi mạng sau khi sửa file /etc/fstab, status check instance lỗi. Cách sửa nhanh nhất không cần tạo máy mới?

Lỗi trong OS, máy không có mạng: Serial Console cho truy cập như cổng console vật lý.

Câu hỏi nhanh. Batch xử lý video chạy mỗi đêm, có thể dừng và chạy lại, cần chi phí thấp nhất. Cách mua?

Tải chịu được gián đoạn là trường hợp lý tưởng của Spot.

Câu hỏi nhanh. Instance c5.large phục vụ API có metric ENA pps_allowance_exceeded tăng và độ trễ tăng, CPU chỉ 30%. Nên làm gì?

Allowance exceeded nghĩa là instance chạm giới hạn mạng của kích thước đó.

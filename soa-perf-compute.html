#EC2: những thứ đề SOA hỏi sâu

Status check

LoạiÝ nghĩaXử lý
System status checkLỗi phía AWS: phần cứng, mạng, nguồn của máy chủ vật lýStop rồi Start (chuyển sang host khác), hoặc auto recovery. Reboot không chuyển host
Instance status checkLỗi bên trong máy: OS không khởi động, hết bộ nhớ, cấu hình mạng sai, file system hỏngReboot, sửa OS, xem System log / screenshot trên console
Attached EBS status checkVolume EBS gắn vào không truy cập đượcKiểm tra volume, stop / start

Lỗi khi khởi chạy

  • InstanceLimitExceeded / VcpuLimitExceeded: chạm service quota theo vCPU. Xin tăng quota qua Service Quotas.
  • InsufficientInstanceCapacity: AZ đó tạm hết loại máy. Đổi AZ, đổi instance type, thử lại sau, hoặc dùng On-Demand Capacity Reservation cho tải quan trọng.
  • Instance chuyển ngay từ pending sang terminated: EBS snapshot hỏng, chạm giới hạn EBS, hoặc AMI cần KMS key mà role không có quyền giải mã.

Hiệu năng mạng và placement group

Placement groupĐặc điểmHợp với

  • Enhanced networking bằng ENA (tới 100 Gbps trở lên), EFA cho HPC / ML (bỏ qua kernel). Cần driver ENA trong AMI và instance type hỗ trợ.
  • Thêm instance vào cluster placement group bị InsufficientInstanceCapacity: stop toàn bộ instance trong group rồi start lại cùng lúc.

Burstable (T-family)

T3 / T4g tích luỹ CPU credit. Hết credit (metric CPUCreditBalance về 0) thì CPU bị kìm xuống mức baseline, ứng dụng chậm hẳn. Cách sửa: bật unlimited mode (trả thêm khi vượt) hoặc đổi sang dòng M / C.

#Auto Scaling ở góc nhìn vận hành

Loại policyCách hoạt động
Target trackingGiữ một metric quanh giá trị đích (CPU 50%, request mỗi target 1000). Dễ nhất, đề hay chọn
Step scalingThêm / bớt số máy theo mức độ vượt ngưỡng của alarm
Simple scalingKiểu cũ, chờ cooldown xong mới phản ứng tiếp
ScheduledTải biết trước (8 giờ sáng thứ Hai)
PredictiveTự học chu kỳ tải hằng ngày / tuần và chuẩn bị máy trước
  • Lifecycle hook: tạm giữ instance ở Pending:Wait (cài phần mềm trước khi nhận tải) hoặc Terminating:Wait (đẩy log, rút khỏi cluster trước khi xoá). Kết hợp EventBridge → Lambda / SSM, xong gọi CompleteLifecycleAction.
  • Warm pool: giữ sẵn instance đã khởi tạo (ở trạng thái stopped) để scale-out nhanh với ứng dụng khởi động lâu.
  • Instance refresh: thay dần toàn bộ instance sang launch template mới (AMI mới), giữ tỉ lệ máy khoẻ tối thiểu.
  • Health check của ASG: mặc định chỉ EC2 status check. Bật ELB health check để thay máy khi ứng dụng chết mà OS còn sống.
  • Health check grace period quá ngắn: máy bị đánh dấu không khoẻ khi ứng dụng chưa kịp khởi động, ASG terminate và launch liên tục (vòng lặp). Tăng grace period.
  • Muốn giữ một máy lại để điều tra: đặt standby hoặc scale-in protection, hoặc suspend process ReplaceUnhealthy, Terminate.
  • Không launch được: launch template tham chiếu AMI đã xoá, key pair không tồn tại, security group ở VPC khác, hết quota.

#Right-sizing và chi phí

  • AWS Compute Optimizer: phân tích metric 14 ngày, đề xuất loại instance, kích thước EBS, cấu hình Lambda, ASG phù hợp. Cần metric bộ nhớ (từ agent) để đề xuất chính xác hơn.
  • Trusted Advisor: kiểm tra instance chạy không tải, EBS không gắn, Elastic IP không dùng. Đầy đủ các check cần gói Business support trở lên.
  • Tag tài nguyên (cost allocation tags) để chia chi phí theo dự án, kết hợp Cost Explorer, AWS Budgets (cảnh báo khi sắp vượt ngân sách).

Câu hỏi nhanh. Ứng dụng web trên ASG sau ALB. Sau khi deploy bản mới, instance mới bị terminate và thay thế liên tục, dù log cho thấy ứng dụng khởi động mất khoảng 4 phút rồi chạy bình thường. Cách sửa?

ELB health check thất bại trong lúc ứng dụng còn đang khởi động. Grace period cho máy thời gian khởi động trước khi bị đánh giá.

Câu hỏi nhanh. Một instance báo StatusCheckFailed_System. Reboot không hết. Cách xử lý đúng?

Lỗi system check là lỗi host. Stop / Start chuyển instance sang host mới, reboot giữ nguyên host.

Câu hỏi nhanh. Trước khi một instance bị scale-in, đội cần chép log ứng dụng trong máy lên S3. Giải pháp?

Lifecycle hook giữ instance lại ở trạng thái chờ để làm việc dọn dẹp trước khi terminate.

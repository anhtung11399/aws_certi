VPC và xử lý sự cố mạng

Subnet, route table, IGW, NAT, SG vs NACL, VPC endpoint, Flow Logs, Reachability Analyzer, IPv6, IPAM, VPC sharing, các lỗi kết nối kinh điển.

Học xong bài này bạn sẽ:
  • Tìm ra vì sao hai máy không nói chuyện được
  • Cấu hình endpoint, NAT đúng

#Thành phần VPC cần nắm chắc

Thành phầnGhi nhớ vận hành
CIDR/16 tới /28. Thêm secondary CIDR khi hết IP. Không trùng CIDR với VPC sẽ peering / on-premises. Mỗi subnet mất 5 IP (.0 network, .1 router, .2 DNS, .3 dự phòng, broadcast)
SubnetThuộc một AZ. Public / private chỉ khác ở route table. "Auto-assign public IPv4" quyết định instance mới có public IP không
Route tableMỗi subnet gắn đúng một route table (không gắn thì dùng main route table). Route cụ thể nhất (longest prefix) thắng. Route local không xoá được
Internet GatewayMột IGW / VPC; cần route 0.0.0.0/0 → igw và public IP / EIP trên instance
NAT GatewayĐặt ở public subnet, có EIP (public NAT) hoặc private NAT (cho mạng nội bộ chồng IP). Mỗi AZ một cái. Tối đa 55.000 kết nối đồng thời tới cùng một đích (IP + port + protocol); vượt → ErrorPortAllocation, thêm IP phụ (tới 8). Không có SG. Chi phí theo giờ + GB xử lý
Egress-only IGWIPv6 đi ra Internet, chặn chiều vào (thay NAT cho IPv6)
Elastic IPIP public tĩnh, tính phí cả khi gắn (từ 2024 mọi IPv4 public đều tính phí)
DHCP option setDNS server, domain name cho VPC
DNS attributesenableDnsSupport (dùng resolver .2), enableDnsHostnames (cấp tên DNS public). Cần cả hai cho private hosted zone và Private DNS của interface endpoint
IPAMQuản lý, cấp phát, theo dõi dải IP cho nhiều VPC / account, phát hiện trùng

#Security group vs NACL

Security groupNACL
Gắn vàoENI (instance, RDS, ALB, endpoint...)Subnet
Trạng tháiStateful: chiều về tự được phépStateless: phải cho phép cả chiều về
RuleChỉ AllowAllow và Deny, đánh số, xét từ nhỏ đến lớn, khớp đầu tiên thì dừng
Mặc địnhSG mới: chặn mọi chiều vào, cho mọi chiều raNACL mặc định: cho tất cả. NACL tự tạo: chặn tất cả
NguồnCIDR, SG khác, prefix listCIDR
  • NACL chặn một IP xấu: thêm rule Deny với số nhỏ hơn rule Allow.
  • NACL phải mở ephemeral ports 1024-65535 cho chiều về (client Linux 32768-60999, Windows 49152-65535, NAT Gateway 1024-65535).
  • SG tham chiếu SG: "DB chỉ nhận từ SG app". Tham chiếu được SG ở VPC peer cùng Region, hoặc qua TGW (tính năng security group referencing).
  • Connection tracking: đổi rule SG không cắt kết nối đang mở đã được theo dõi; NACL cắt ngay.

Dịch vụS3, DynamoDBHầu hết dịch vụ AWS, dịch vụ của đối tác / của bạn
Cách hoạt độngThêm route (prefix list) vào route tableENI có IP private trong subnet
Chi phíMiễn phíTheo giờ mỗi AZ + GB
Truy cập từ on-premises / VPC peerKhôngCó
Bảo vệEndpoint policyEndpoint policy + security group
  • Endpoint policy mặc định cho phép tất cả; thu hẹp: chỉ bucket của công ty (aws:ResourceOrgID).
  • Interface endpoint lỗi: SG của endpoint chưa cho 443 từ nguồn; Private DNS tắt hoặc VPC thiếu DNS attributes nên tên dịch vụ vẫn phân giải ra IP public.
  • Interface endpoint cho S3 dùng tên DNS riêng của endpoint (hoặc Private DNS cho S3), hợp khi cần truy cập từ on-premises.

#Công cụ chẩn đoán

VPC Flow Logs

Định dạng mặc định (version 2)
version account-id interface-id srcaddr dstaddr srcport dstport protocol packets bytes start end action log-status
2 111122223333 eni-0abc 10.0.1.25 52.94.1.10 49152 443 6 10 840 1700000000 1700000060 ACCEPT OK
  • Bật ở VPC, subnet hoặc ENI (kể cả ENI của ELB, NAT, RDS, Transit Gateway có flow log riêng). Đích: CloudWatch Logs, S3 (Parquet, partition theo giờ), Firehose.
  • Custom format thêm trường: vpc-id, subnet-id, instance-id, tcp-flags, pkt-srcaddr / pkt-dstaddr (IP thật khi đi qua NAT / ELB), flow-direction, traffic-path.
  • Không ghi: traffic tới DNS của Amazon (.2), metadata 169.254.169.254, DHCP, Windows license activation, time sync 169.254.169.123.
  • Đọc: inbound ACCEPT + outbound REJECT → NACL chặn chiều về. REJECT cả hai chiều → SG hoặc NACL chặn chiều vào.
  • Phân tích bằng CloudWatch Logs Insights, Athena; dữ liệu không thời gian thực (gom 1 hoặc 10 phút).

Reachability Analyzer và các công cụ khác

  • Reachability Analyzer: phân tích tĩnh cấu hình từ nguồn tới đích (instance, ENI, IGW, TGW, VPN, endpoint...), chỉ rõ thành phần chặn (SG, NACL, route). Không gửi gói tin.
  • Network Access Analyzer: tìm các đường truy cập vi phạm yêu cầu ("không có đường từ Internet tới subnet database").
  • Traffic Mirroring: sao chép gói tin thật tới thiết bị phân tích (IDS, gỡ lỗi sâu).
  • Network Manager / Infrastructure Performance: độ trễ giữa AZ / Region của mạng AWS.
  • Trên máy: curl -v, nc -zv host port, traceroute, dig, ss -tnp.

Instance private không ra InternetRoute 0.0.0.0/0 → NAT; NAT nằm ở public subnet có route tới IGW; NAT ở trạng thái available; NACL của cả subnet private và subnet NAT
Không SSH đượcSG cho 22 từ IP của bạn, NACL cả hai chiều, instance có public IP, key đúng, user đúng, OS firewall; tốt hơn: Session Manager / EC2 Instance Connect Endpoint
ALB không tới được targetSG của target cho SG của ALB ở cổng ứng dụng; NACL subnet target; health check path

Tên miền nội bộ không phân giảiDNS attributes của VPC, private hosted zone đã liên kết VPC chưa, Resolver rule

#VPC sharing và IPv6

  • VPC sharing (qua RAM): account chủ quản lý VPC / subnet / route; account tham gia tạo EC2, RDS, Lambda... trong subnet được chia sẻ. Giảm số VPC, dùng chung NAT / endpoint.
  • IPv6: dải /56 cho VPC, /64 cho subnet, mọi địa chỉ đều public (định tuyến được), dùng egress-only IGW để chặn chiều vào. Dual-stack hoặc IPv6-only subnet.
  • VPC Block Public Access: chặn mọi đường Internet vào / ra VPC ở cấp account / Region (có ngoại lệ).

Câu hỏi nhanh. Instance trong private subnet ra Internet qua NAT Gateway nhưng kết nối tới một API đối tác bị lỗi ngắt quãng khi tải cao. CloudWatch cho thấy ErrorPortAllocation tăng. Cách sửa?

NAT bị cạn cổng nguồn khi quá nhiều kết nối đồng thời tới cùng một đích; thêm IP tăng số cổng khả dụng.

Câu hỏi nhanh. Flow Logs cho một ENI ghi inbound ACCEPT tới cổng 443 nhưng outbound REJECT cho gói trả lời. Thành phần nào gây lỗi?

SG stateful không chặn chiều trả lời. NACL stateless có thể chặn.

Câu hỏi nhanh. Máy on-premises qua VPN cần đọc S3 bằng kết nối riêng tư tới VPC. Gateway endpoint S3 đã có nhưng không dùng được từ on-premises. Giải pháp?

Gateway endpoint chỉ dùng được từ trong VPC; interface endpoint truy cập được qua VPN / DX.

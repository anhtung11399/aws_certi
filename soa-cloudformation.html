#CloudFormation: những gì cần nắm chắc

Cấu trúc template

template.yaml (rút gọn)
Parameters:
  Env: { Type: String, AllowedValues: [dev, prod] }
  LatestAmi:                       # lấy AMI mới nhất từ Parameter Store, không ghi cứng ID
    Type: AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>
    Default: /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64
Mappings:                          # bảng tra cố định, ví dụ theo Region
  Sizes: { dev: { Type: t3.micro }, prod: { Type: m7g.large } }
Conditions:
  IsProd: !Equals [!Ref Env, prod]
Resources:
  Db:
    Type: AWS::RDS::DBInstance
    DeletionPolicy: Snapshot       # xoá stack thì chụp snapshot thay vì mất dữ liệu
    UpdateReplacePolicy: Snapshot  # bị thay thế khi update thì cũng chụp snapshot
    Properties: { ... }
Outputs:
  DbEndpoint:
    Value: !GetAtt Db.Endpoint.Address
    Export: { Name: !Sub "${AWS::StackName}-DbEndpoint" }   # stack khác dùng !ImportValue
  • Hàm hay gặp: !Ref, !GetAtt, !Sub, !Join, !FindInMap, !If, !ImportValue.
  • DeletionPolicy: Delete (mặc định), Retain (giữ tài nguyên), Snapshot (EBS, RDS, ElastiCache, Redshift...).
  • Export đang được stack khác ImportValue thì không sửa / xoá được stack xuất. Phải gỡ import trước.
  • Secret không ghi trong template: dùng dynamic reference {{resolve:secretsmanager:...}} hoặc {{resolve:ssm-secure:...}}, tham số dùng NoEcho.

Intrinsic function và pseudo parameter

HàmDùng
!RefGiá trị parameter, hoặc ID mặc định của tài nguyên (ví dụ instance ID, tên bucket)
!GetAtt Res.AttrThuộc tính khác của tài nguyên (ARN, DNS name, endpoint)
!SubGhép chuỗi có biến: !Sub "arn:aws:s3:::${BucketName}/*"
!Join, !Split, !SelectXử lý chuỗi / danh sách
!FindInMapTra Mappings theo Region / môi trường
!GetAZs, !CidrDanh sách AZ, chia dải CIDR
!If, !Equals, !And, !Or, !NotĐiều kiện; AWS::NoValue để bỏ một thuộc tính
!ImportValueLấy Output được export từ stack khác cùng Region
Fn::Transform, Transform: AWS::Serverless-2016-10-31Macro; SAM cho serverless; AWS::Include chèn đoạn template từ S3

Pseudo parameter: AWS::Region, AWS::AccountId, AWS::StackName, AWS::StackId, AWS::Partition, AWS::URLSuffix, AWS::NoValue.

Parameter

  • Kiểu đặc biệt kiểm tra giá trị có thật: AWS::EC2::KeyPair::KeyName, AWS::EC2::VPC::Id, List<AWS::EC2::Subnet::Id>, AWS::SSM::Parameter::Value<...>.
  • Ràng buộc: AllowedValues, AllowedPattern, MinLength, ConstraintDescription. NoEcho: true để không hiển thị giá trị.
  • Dynamic reference: {{resolve:ssm:/app/ami}}, {{resolve:ssm-secure:/db/pass}} (chỉ một số thuộc tính hỗ trợ), {{resolve:secretsmanager:prod/db:SecretString:password}}. Tốt hơn: ManageMasterUserPassword: true cho RDS để RDS tự quản lý secret.

Thứ tự tạo và phụ thuộc

  • CloudFormation tự suy phụ thuộc từ !Ref / !GetAtt. Phụ thuộc ngầm (ví dụ instance cần route tới Internet Gateway đã gắn xong) thì dùng DependsOn.
  • Custom resource: gọi Lambda (hoặc SNS) để làm việc CloudFormation không hỗ trợ sẵn (tra cứu, làm rỗng bucket trước khi xoá). Lambda phải gửi phản hồi về pre-signed URL, nếu không stack treo tới timeout (1 giờ).
  • Nested stack (AWS::CloudFormation::Stack): chia template lớn, dùng lại thành phần; cập nhật qua stack cha. Khác cross-stack reference (Export / ImportValue) giữa các stack độc lập.
  • Giới hạn: template 1 MB (từ S3), 500 tài nguyên mỗi stack, 200 parameter, 200 output.

Update behavior của tài nguyên

KiểuVí dụ
Update with no interruptionĐổi tag, đổi một số thuộc tính của SG
Update with some interruptionĐổi instance type của EC2 (stop / start)
ReplacementĐổi tên bucket, đổi DBInstanceIdentifier, đổi AZ của subnet: tạo mới rồi xoá cũ (mất dữ liệu nếu không có UpdateReplacePolicy)

Tài nguyên có tên cố định (custom name) không thể bị replace vì trùng tên: update thất bại. Để CloudFormation tự sinh tên nếu có thể.

Cập nhật an toàn

  • Change set: xem trước thay đổi, đặc biệt cột Replacement (tài nguyên sẽ bị xoá và tạo mới, ví dụ đổi tên RDS instance).
  • Stack policy: chặn update lên tài nguyên quan trọng (ví dụ cấm thay thế database).
  • Termination protection: chặn xoá cả stack.
  • Drift detection: phát hiện ai đó sửa tay tài nguyên ngoài CloudFormation.
  • Rollback configuration: gắn CloudWatch alarm, alarm kêu trong lúc update thì tự rollback.
  • Bật termination protection và DeletionPolicy cho dữ liệu là câu trả lời cho "tránh mất dữ liệu khi xoá stack nhầm".

Đưa tài nguyên có sẵn vào và tách ra

  • Resource import: đưa tài nguyên đã tạo tay vào stack (cần DeletionPolicy trong template). IaC generator: quét tài nguyên có sẵn và sinh template.
  • Tách tài nguyên khỏi stack mà không xoá: đặt DeletionPolicy: Retain, update, rồi xoá khỏi template.
  • CloudFormation Hooks: kiểm tra tài nguyên trước khi tạo / sửa (ví dụ bắt buộc mã hoá), có thể dùng Guard rule hoặc Lambda.
  • Git sync: stack tự cập nhật khi template trong repo Git thay đổi.
  • cfn-lint kiểm tra cú pháp, cfn-guard kiểm tra chính sách, aws cloudformation validate-template.

#StackSets: nhiều account, nhiều Region

  • Deploy cùng một template ra nhiều account và Region trong một thao tác.
  • Quyền: self-managed (tự tạo role AWSCloudFormationStackSetAdministrationRole ở account quản trị và AWSCloudFormationStackSetExecutionRole ở account đích) hoặc service-managed (dùng Organizations, có automatic deployment cho account mới vào OU).
  • Tuỳ chọn: maximum concurrent accounts, failure tolerance, thứ tự Region.

"Mọi account mới trong Organization phải tự động có CloudTrail / Config / IAM role chuẩn" → StackSets service-managed với automatic deployment gắn vào OU (hoặc Control Tower).

StackSets chi tiết

  • Stack instance = một stack trong một account + Region của StackSet.
  • Thao tác: create, update, delete stack instances, override parameter cho từng account / Region.
  • Lỗi hay gặp: execution role thiếu ở account đích hoặc trust policy sai account quản trị; account đích chưa bật Region (opt-in Region); vượt failure tolerance làm dừng cả thao tác; tài nguyên có tên trùng (bucket toàn cầu) khi deploy nhiều Region.
  • Service-managed: dùng delegated administrator để không phải làm việc ở management account; automatic deployment khi account vào / rời OU (tuỳ chọn giữ hay xoá stack khi rời).
  • Không deploy vào management account bằng service-managed permission.

#AWS CDK, Terraform

  • CDK: viết hạ tầng bằng TypeScript / Python..., cdk synth sinh template CloudFormation, cdk deploy triển khai. Lần đầu mỗi account / Region phải cdk bootstrap (tạo bucket, role cho CDK). Lỗi "không tìm thấy bucket staging" → chưa bootstrap.
  • CDK có construct L1 (tương ứng 1-1 tài nguyên CloudFormation), L2 (mặc định hợp lý), L3 (pattern nhiều tài nguyên). cdk diff xem thay đổi trước khi deploy. CDK Pipelines để deploy nhiều môi trường.
  • AWS SAM: mở rộng CloudFormation cho serverless (AWS::Serverless::Function), sam build, sam deploy, deploy Lambda an toàn bằng CodeDeploy (canary / linear).
  • Bên thứ ba: Terraform (state lưu ở S3 + khoá DynamoDB / S3 native locking), Git làm nguồn sự thật cho IaC.

Câu hỏi nhanh. Stack ở trạng thái UPDATE_ROLLBACK_FAILED vì một Lambda trong stack đã bị xoá thủ công. Làm gì?

ContinueUpdateRollback cho phép đưa stack về UPDATE_ROLLBACK_COMPLETE, bỏ qua tài nguyên không còn tồn tại.

Câu hỏi nhanh. Template tạo EC2 cài phần mềm bằng user data. Stack báo CREATE_COMPLETE dù script cài đặt lỗi. Cần gì để stack chỉ hoàn tất khi cài xong?

CloudFormation coi instance xong khi API trả về. CreationPolicy + cfn-signal bắt nó chờ tín hiệu thành công từ trong máy.

Câu hỏi nhanh. Cần đảm bảo database RDS không bị mất khi ai đó xoá stack. Chọn 2 đáp án.

DeletionPolicy bảo vệ dữ liệu khi tài nguyên bị xoá, termination protection chặn việc xoá stack ngay từ đầu.

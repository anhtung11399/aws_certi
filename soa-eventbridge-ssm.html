EventBridge và Systems Manager: tự động khắc phục

Event bus, rule, target; SSM Run Command, Automation runbook, Patch Manager, State Manager, Session Manager, Parameter Store.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Ghép alarm / event với hành động tự khắc phục
  • Chọn đúng công cụ SSM cho từng việc
  • Vá lỗi máy chủ hàng loạt an toàn

#EventBridge: bộ định tuyến sự kiện

Hầu hết thay đổi trong AWS sinh ra một event (dạng JSON): instance đổi trạng thái, alarm đổi trạng thái, API call được CloudTrail ghi lại, GuardDuty có finding, lịch hẹn giờ... EventBridge nhận event vào event bus, rule lọc event theo mẫu, rồi gửi tới target.

Event pattern: EC2 bị stop
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": { "state": ["stopped", "terminated"] }
}
  • Default bus nhận event của dịch vụ AWS. Custom bus cho ứng dụng của bạn. Partner bus cho SaaS (Datadog, Zendesk...).
  • Gửi event sang account / Region khác: target là event bus của account kia, bus đó cần resource policy cho phép.
  • Input transformer: sửa event trước khi gửi (lấy vài trường, ghép thành câu thông báo). Đề hay gọi là "enrich / customize the notification".
  • Target lỗi: EventBridge thử lại tới 24 giờ, cấu hình DLQ (SQS) để giữ event không gửi được.
  • EventBridge Scheduler: hẹn giờ chạy (cron, rate, một lần), thay cho rule schedule kiểu cũ, nhiều target hơn.
  • Rule không chạy? Kiểm tra: event có đúng ở Region đó không (nhiều dịch vụ global như IAM gửi event ở us-east-1), pattern có khớp đúng hoa thường, target có quyền (Lambda resource policy cho events.amazonaws.com, hoặc IAM role của rule).

Event "AWS API Call via CloudTrail" chỉ có khi CloudTrail đang ghi management events trong Region đó. Bắt API của IAM, CloudFront, Route 53 (dịch vụ global) phải đặt rule ở us-east-1.

#Systems Manager: bộ công cụ vận hành

Điều kiện để SSM quản lý một máy (gọi là managed node): có SSM Agent (có sẵn trên Amazon Linux, Windows AMI của AWS), có IAM role với AmazonSSMManagedInstanceCore, và kết nối được tới endpoint SSM (qua Internet / NAT, hoặc VPC endpoint ssm, ssmmessages, ec2messages). Thiếu một trong ba là máy không hiện trong Fleet Manager.

Tính năngDùng khi đề nói
Run Command"Chạy một lệnh / script trên nhiều máy ngay bây giờ", không cần SSH. Chọn máy theo tag, giới hạn tốc độ (rate control) và ngưỡng lỗi
Automation (runbook)"Quy trình nhiều bước": tạo AMI, khôi phục instance, sửa cấu hình. Có sẵn runbook AWS-*, ví dụ AWS-RestartEC2Instance, AWSSupport-ResetAccess (lấy lại quyền vào máy mất key). Gọi được từ EventBridge, Config remediation, alarm
Patch Manager"Vá lỗi hệ điều hành định kỳ". Patch baseline (quy tắc vá gì), patch group (tag Patch Group), lịch chạy trong Maintenance Window, báo cáo compliance
State Manager"Đảm bảo máy luôn ở một trạng thái": agent luôn được cài, cấu hình luôn đúng. Áp lại định kỳ (association)
Maintenance Windows"Chỉ làm việc gây gián đoạn trong khung giờ cho phép"
Session Manager"Vào shell của máy mà không mở cổng 22, không bastion, có log phiên". Ghi log phiên về S3 / CloudWatch Logs
Parameter StoreLưu cấu hình, chuỗi kết nối. SecureString mã hoá bằng KMS. Standard miễn phí (tới 4 KB), Advanced (8 KB, có parameter policy hết hạn)
Inventory"Liệt kê phần mềm đã cài trên mọi máy"
OpsCenter / Incident ManagerGom sự cố vận hành (OpsItem), quy trình trực sự cố, gọi người trực
DistributorĐóng gói và phân phối phần mềm (agent của bên thứ ba)
Change Manager / Change CalendarPhê duyệt thay đổi, chặn thay đổi trong giai đoạn đóng băng

Mẫu hay gặp nhất trong đề: Config rule phát hiện tài nguyên sai (ví dụ S3 bucket public, security group mở 0.0.0.0/0 cổng 22) → remediation action là một SSM Automation runbook tự sửa. Có thể đặt automatic remediation (tự chạy, có số lần thử lại).

#AWS Health

  • AWS Health Dashboard: sự cố của AWS ảnh hưởng tới tài nguyên của bạn, lịch bảo trì (ví dụ EC2 sắp bị retire do phần cứng). Event của Health có trong EventBridge, nên tự động hoá được: "khi có lịch retire instance thì tự stop / start để chuyển sang phần cứng mới".
  • Tổng hợp Health event cho cả Organization: bật organizational view.

Câu hỏi nhanh. Công ty cần vá bản cập nhật bảo mật cho 300 EC2 Windows và Linux mỗi Chủ nhật 2 giờ sáng, có báo cáo máy nào chưa vá. Giải pháp?

Patch Manager + Maintenance Window đúng tình huống "vá định kỳ có lịch và có báo cáo compliance".

Câu hỏi nhanh. EC2 trong private subnet (không có NAT) không xuất hiện trong Systems Manager dù đã gắn role đúng. Cần thêm gì?

SSM Agent phải gọi ra endpoint của SSM. Không có đường ra Internet thì cần VPC endpoint, không cần mở cổng vào nào.

Câu hỏi nhanh. Rule EventBridge bắt sự kiện DeleteUser của IAM được tạo ở ap-southeast-1 nhưng không bao giờ chạy. Nguyên nhân có khả năng nhất?

API của dịch vụ global như IAM được ghi nhận ở us-east-1, rule phải đặt ở đó.

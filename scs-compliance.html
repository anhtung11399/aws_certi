Triển khai nhất quán và tuân thủ

IaC an toàn (StackSets, Guard, cfn-lint, Hooks), tag, Firewall Manager, Service Catalog, RAM, Config / Security Hub, Audit Manager, Artifact, Well-Architected.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Triển khai an toàn, nhất quán nhiều account
  • Phát hiện và sửa tài nguyên không tuân thủ
  • Thu thập bằng chứng kiểm toán

#Triển khai nhất quán bằng IaC

  • CloudFormation StackSets (service-managed, automatic deployment theo OU, delegated admin), Terraform, CDK; mọi thay đổi qua pipeline, không sửa tay trên console production.
  • cfn-lint: lỗi cú pháp, giá trị sai, best practice. CloudFormation Guard: policy-as-code ("mọi bucket phải bật mã hoá và Block Public Access", "SG không mở 0.0.0.0/0 cổng 22"), chạy trong CI hoặc dưới dạng Config custom rule / Hook. CloudFormation Hooks: chặn tạo / sửa tài nguyên không tuân thủ ngay lúc deploy (Lambda hoặc Guard hook, managed proactive control của Control Tower).
  • IaC bên thứ ba: Terraform với Sentinel / OPA, Checkov, tfsec.
  • Không đưa secret vào template: dynamic reference, ManageMasterUserPassword.

#Tag để tổ chức và kiểm soát

  • Gom tài nguyên theo phòng ban, cost center, môi trường, mức độ nhạy cảm dữ liệu (DataClassification), chủ sở hữu.
  • Tag policy chuẩn hoá; SCP bắt buộc tag khi tạo (aws:RequestTag, aws:TagKeys); Config rule required-tags.
  • Dùng tag cho ABAC, cho backup plan, cho patch group, cho Firewall Manager scope, cho Resource Groups.
  • Chặn người dùng tự đổi tag dùng cho phân quyền (Deny TagResource / UntagResource với các key nhạy cảm).

#Áp chính sách từ một nơi: Firewall Manager

Loại policyTác dụng
WAFGắn web ACL chung (first / last rule groups) cho mọi ALB / CloudFront / API Gateway trong scope, kể cả tài nguyên mới
Shield AdvancedTự đăng ký tài nguyên vào Shield Advanced
Security groupCommon SG (gắn SG chuẩn), content audit (cấm rule quá rộng), usage audit (SG không dùng / trùng)
Network FirewallTự tạo firewall và route trong VPC (distributed / centralized)
Route 53 Resolver DNS FirewallGắn rule group cho mọi VPC
Third-party firewallPalo Alto Cloud NGFW, Fortigate

Yêu cầu: Organizations, Firewall Manager administrator (delegated), AWS Config bật ở các account trong scope. Scope chọn theo account, OU, tag tài nguyên.

#Chia sẻ tài nguyên an toàn

  • AWS RAM: chia sẻ subnet, TGW, Resolver rules, prefix list, Private CA, License Manager... chỉ trong Organization (tắt chia sẻ ra ngoài bằng setting / SCP ram:RequestedAllowsExternalPrincipals). Managed permission quyết định người nhận được làm gì.
  • Service Catalog: portfolio sản phẩm đã duyệt; launch constraint (role của Service Catalog tạo tài nguyên, người dùng không cần quyền trực tiếp); template constraint (giới hạn tham số, ví dụ chỉ instance type nhỏ); TagOptions; chia sẻ portfolio cho OU.

#Đánh giá tuân thủ

Dịch vụVai trò
AWS ConfigRule (managed / Lambda / Guard), remediation tự động, conformance pack (mẫu theo chuẩn), aggregator nhiều account / Region, organization rule, advanced query, proactive evaluation
Security HubControl theo tiêu chuẩn, security score, gửi finding tới EventBridge để tự xử lý, automation rules
Audit ManagerFramework dựng sẵn (SOC 2, PCI DSS, HIPAA, GDPR, NIST, CIS, ISO 27001...) hoặc tự tạo; tự thu thập bằng chứng từ Config, Security Hub, CloudTrail, API; người phụ trách xem xét (delegation), xuất assessment report cho kiểm toán viên
AWS ArtifactTải báo cáo tuân thủ của AWS (SOC 1/2/3, ISO, PCI AOC) và quản lý thoả thuận (BAA cho HIPAA)
Well-Architected ToolTự đánh giá kiến trúc theo các trụ cột (Security Pillar), lens (Serverless, SaaS...), milestone, danh sách rủi ro cao / trung bình và kế hoạch cải thiện
Trusted AdvisorCheck bảo mật cơ bản (MFA root, SG mở, bucket public)

"Kiểm toán viên cần báo cáo SOC 2 của AWS" → Artifact. "Thu thập bằng chứng hệ thống của công ty theo PCI DSS" → Audit Manager. "Kiểm tra liên tục cấu hình theo CIS và tự sửa" → Config conformance pack + remediation / Security Hub.

Câu hỏi nhanh. Mọi ALB mới tạo ở mọi account trong OU Prod phải tự động có web ACL chuẩn của công ty và bảo vệ Shield Advanced. Giải pháp ít công sức nhất?

Firewall Manager tự áp chính sách cho tài nguyên hiện có và tài nguyên mới trong scope.

Câu hỏi nhanh. Developer cần tự tạo môi trường thử nghiệm đúng chuẩn công ty nhưng không được có quyền tạo VPC, IAM role trực tiếp. Dịch vụ?

Launch constraint để Service Catalog tạo tài nguyên bằng role riêng thay người dùng.

Câu hỏi nhanh. Pipeline cần chặn merge nếu template tạo bucket S3 không bật mã hoá. Công cụ phù hợp nhất ở bước CI?

Guard là policy-as-code kiểm tra template trước khi deploy.

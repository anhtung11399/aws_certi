AMI, container image và chia sẻ tài nguyên

EC2 Image Builder, quản lý AMI, ECR, chia sẻ AMI / snapshot, AWS RAM, Service Catalog, Service Quotas.

Học xong bài này bạn sẽ:
  • Dựng image chuẩn tự động
  • Chia sẻ tài nguyên giữa account an toàn

#AMI: vòng đời

  • AMI gồm: snapshot EBS của các volume, launch permission, block device mapping. AMI là tài nguyên theo Region: dùng ở Region khác phải copy.
  • Tạo AMI từ instance: mặc định instance bị reboot để file system nhất quán (có tuỳ chọn no-reboot nhưng có thể không nhất quán).
  • Chia sẻ AMI: thêm account ID / Organization / OU vào launch permission. AMI có snapshot mã hoá: phải dùng customer managed key và cấp quyền key cho account nhận (kms:CreateGrant, Decrypt, DescribeKey, ReEncrypt, GenerateDataKey). AMI mã hoá bằng aws/ebs không chia sẻ được: copy lại với customer managed key.
  • Block public access for AMIs bật mặc định cho account mới: chặn chia sẻ công khai.
  • Deprecate AMI (ẩn khỏi danh sách nhưng vẫn launch được bằng ID), disable AMI, deregister (không launch được, snapshot vẫn còn và vẫn tính phí cho tới khi xoá). Recycle Bin giữ AMI bị deregister nhầm.
  • Allowed AMIs (cấu hình account / declarative policy): chỉ cho launch AMI từ nhà cung cấp / account được phép.
  • AMI Marketplace / có product code: không copy sang account khác được theo cách thông thường.
  • Lấy AMI mới nhất của AWS qua Parameter Store public parameter thay vì ghi cứng ID (ID khác nhau theo Region).

#EC2 Image Builder

  • Component: tài liệu YAML gồm các bước build / validate / test. Có sẵn component của AWS (cập nhật Linux, CIS hardening STIG, cài CloudWatch agent...).
  • Infrastructure configuration: instance type, subnet, SG, IAM instance profile (cần EC2InstanceProfileForImageBuilder và SSM), nơi ghi log (S3).
  • Distribution settings: Region đích, account đích, cập nhật launch template (ASG dùng AMI mới), KMS key.
  • Schedule: theo cron hoặc khi có bản cập nhật của image gốc / component.
  • Lifecycle policy: tự deprecate / xoá AMI cũ.
  • Dựng được cả container image đẩy lên ECR.
  • Pipeline lỗi: xem log trong S3 / CloudWatch, build instance không kết nối được SSM (thiếu role / mạng), component lỗi.

"Tạo golden AMI đã vá, kiểm thử, phân phối sang nhiều Region / account một cách tự động, ít công sức" → EC2 Image Builder. Đáp án tự viết Lambda + SSM Automation hay Packer trên EC2 thường nhiều công sức hơn.

#Container image: Amazon ECR

  • Repository private / public. Lifecycle policy xoá image cũ (giữ N image gần nhất, xoá image untagged sau N ngày).
  • Image scanning: basic (quét lúc push / thủ công, CVE hệ điều hành) hoặc enhanced (Inspector, quét liên tục cả thư viện ngôn ngữ).
  • Tag immutability: không ghi đè tag (tránh latest bị thay âm thầm).
  • Replication cross-Region / cross-account. Pull through cache từ Docker Hub, Quay, GitHub... Repository policy để cho account khác pull.
  • Pull lỗi trên ECS / EKS: execution role thiếu ecr:GetAuthorizationToken, BatchGetImage; private subnet thiếu endpoint ecr.api, ecr.dkr và gateway endpoint s3 (layer nằm ở S3).

#Chia sẻ tài nguyên giữa account: AWS RAM

Chia sẻ được (ví dụ)Ứng dụng
Subnet (VPC sharing)Account mạng sở hữu VPC, account ứng dụng tạo tài nguyên trong subnet được chia sẻ. Account tham gia không sửa được VPC, route table, NACL; tự quản lý SG và tài nguyên của mình
Transit GatewayMọi account gắn VPC vào TGW trung tâm
Route 53 Resolver rules, DNS Firewall rule groupsPhân giải DNS on-premises thống nhất
Prefix list, IPAM poolDải IP dùng chung
License Manager configurations, Capacity Reservations, Dedicated HostsDùng chung giấy phép / capacity
Aurora DB cluster (clone), Glue catalog, Outposts, Network Firewall policy, Private CA...
  • Trong Organization: bật "sharing with AWS Organizations" để chia sẻ không cần lời mời chấp nhận; ngoài Organization phải accept invitation.
  • Có thể giới hạn chỉ chia sẻ trong Organization bằng SCP / RAM settings.

#Service Catalog và Service Quotas

  • Service Catalog: danh mục sản phẩm (template CloudFormation / Terraform) đã được phê duyệt. Người dùng launch qua catalog mà không cần quyền tạo tài nguyên trực tiếp, nhờ launch constraint (role của Service Catalog). Có TagOptions bắt buộc tag, chia sẻ portfolio cho Organization.
  • Service Quotas: xem và xin tăng giới hạn (vCPU, EIP, VPC...), dùng quota request template để account mới tự xin tăng; tạo CloudWatch alarm trên usage của quota.
  • Trusted Advisor có check "Service Limits" và gửi event khi gần chạm.

Câu hỏi nhanh. Account B không launch được AMI mà account A đã chia sẻ. AMI có snapshot mã hoá bằng customer managed key của A. Thiếu gì?

Snapshot mã hoá cần cả quyền launch AMI lẫn quyền dùng KMS key.

Câu hỏi nhanh. Mỗi tháng đội phải dựng AMI mới với bản vá OS và agent bảo mật, chạy kiểm thử, rồi cập nhật launch template của ASG ở 3 Region. Giải pháp ít công sức nhất?

Image Builder bao trọn build, test, distribution và cập nhật launch template.

Câu hỏi nhanh. ECS Fargate task trong private subnet (không NAT) không kéo được image từ ECR. Chọn 2 thứ cần có.

ECR cần API và registry endpoint; các layer image được lưu trên S3 nên cần cả endpoint S3.

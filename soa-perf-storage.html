Storage: EBS, S3, EFS, FSx, DataSync

Loại EBS và giới hạn, Elastic Volumes, snapshot, FSR, S3 performance, multipart, Transfer Acceleration, lifecycle, storage class, EFS / FSx, DataSync, Storage Gateway.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Chọn và chỉnh EBS theo IOPS / throughput
  • Tăng tốc và tiết kiệm S3
  • Chọn shared storage đúng

#EBS chi tiết

  • Volume nằm trong một AZ, chỉ gắn với instance cùng AZ. Muốn chuyển AZ / Region: snapshot rồi tạo / copy.
  • Multi-Attach (io1 / io2): gắn một volume cho tới 16 instance Nitro trong cùng AZ, ứng dụng phải dùng file system hỗ trợ cluster (không dùng ext4 / xfs thường).
  • Elastic Volumes: tăng dung lượng, đổi loại, đổi IOPS / throughput khi đang chạy. Trạng thái modifying → optimizing → completed. Lần sửa tiếp phải chờ ít nhất 6 giờ. Không giảm dung lượng được.
  • Hiệu năng thực tế = min(giới hạn volume, giới hạn EBS bandwidth / IOPS của instance). Instance nhỏ gắn volume lớn vẫn chậm.
  • RAID 0 nhiều volume để vượt giới hạn một volume (hiếm khi cần với io2 Block Express). Không dùng RAID 5 / 6 trên EBS.
  • Metric chẩn đoán: VolumeQueueLength cao kéo dài (thiếu IOPS), VolumeThroughputPercentage, VolumeIdleTime, BurstBalance. Ước tính IOPS = (ReadOps + WriteOps) / số giây của period. Độ trễ trung bình = VolumeTotalReadTime / VolumeReadOps.
  • Instance store: ổ NVMe gắn liền máy, cực nhanh, mất khi stop / terminate / hỏng host. Chỉ cho dữ liệu tạm, cache, bản sao.

Snapshot

  • Incremental, lưu trong S3 do AWS quản lý, có thể chụp khi volume đang dùng (nên flush / dừng ghi để nhất quán; với nhiều volume dùng multi-volume snapshot crash-consistent).
  • Copy sang Region khác, đổi / thêm mã hoá khi copy. Chia sẻ cho account khác (snapshot mã hoá: phải dùng customer managed key và chia sẻ cả key).
  • Fast Snapshot Restore: volume tạo ra có hiệu năng đầy đủ ngay, bật theo AZ, tính phí theo giờ. Không có FSR thì phải "làm nóng" bằng cách đọc toàn bộ block (fio / dd).
  • Data Lifecycle Manager: chính sách tự chụp / giữ / copy cross-Region snapshot và AMI theo tag, có thể chạy script trước / sau khi chụp (pre / post script qua SSM) cho ứng dụng nhất quán.
  • Recycle Bin: rule giữ snapshot / AMI bị xoá trong N ngày để khôi phục; có thể khoá rule.
  • Snapshot Archive: rẻ hơn 75%, giữ tối thiểu 90 ngày, khôi phục 24-72 giờ.
  • Block public access for snapshots: chặn chia sẻ công khai ở cấp Region.

Mã hoá EBS

  • Mã hoá bằng KMS, trong suốt với OS, mã hoá cả dữ liệu, snapshot, dữ liệu truyền giữa instance và volume.
  • EBS encryption by default theo Region: mọi volume mới đều mã hoá.
  • Volume chưa mã hoá → mã hoá: snapshot → copy có mã hoá → tạo volume → thay. Hoặc tạo volume mới từ snapshot chưa mã hoá với tuỳ chọn mã hoá.

#S3: hiệu năng

  • 3.500 PUT/COPY/POST/DELETE và 5.500 GET/HEAD mỗi giây mỗi prefix, không giới hạn số prefix. Lỗi 503 Slow Down khi vượt: phân tán prefix, thêm retry với exponential backoff.
  • Multipart upload: phần 5 MiB – 5 GiB, tối đa 10.000 phần, object tới 5 TiB (bản mới tới 50 TiB). Khuyên dùng từ 100 MB, bắt buộc với object trên 5 GB. AWS CLI aws s3 cp tự dùng multipart.
  • Byte-range GET để tải song song và đọc một phần file.
  • Transfer Acceleration: upload / download qua edge location, endpoint bucketname.s3-accelerate.amazonaws.com; tên bucket không được có dấu chấm; có công cụ Speed Comparison.
  • Client trong cùng Region: dùng gateway endpoint để không qua NAT (rẻ hơn, ổn định).
  • S3 Express One Zone: lớp lưu trữ độ trễ một chữ số mili giây trong một AZ (directory bucket), cho ML / phân tích cần đọc ghi cực nhanh.
  • S3 Select (đọc một phần dữ liệu CSV / JSON) không còn cho khách hàng mới; thay bằng Athena.
  • KMS: SSE-KMS gọi KMS mỗi object; bật S3 Bucket Key để giảm 99% request KMS (tránh ThrottlingException, giảm chi phí).

  • Lifecycle rule: transition (chuyển lớp) và expiration (xoá) cho current / noncurrent versions, xoá expired delete markers, AbortIncompleteMultipartUpload. Lọc theo prefix, tag, kích thước object.
  • Object nhỏ hơn 128 KB không đáng chuyển sang IA (bị tính như 128 KB).
  • S3 Storage Lens: dashboard dung lượng, số object, bucket không có lifecycle / không mã hoá, upload dở dang, cho cả Organization. S3 Inventory: danh sách object (CSV / Parquet) hằng ngày để kiểm tra mã hoá, replication. Storage Class Analysis: gợi ý khi nào chuyển IA.
  • S3 Batch Operations: chạy một thao tác trên hàng tỉ object (copy, đổi tag, đổi lớp, khôi phục Glacier, gọi Lambda, replicate object cũ).
  • Requester Pays: người tải trả phí truyền dữ liệu.

#S3 Event Notifications

  • Sự kiện: s3:ObjectCreated:*, ObjectRemoved, ObjectRestore, Replication, LifecycleExpiration...
  • Đích: SNS, SQS (không FIFO), Lambda, hoặc EventBridge (bật một lần cho bucket, lọc phức tạp, nhiều target, archive / replay).
  • Thông báo không gửi được: thiếu resource policy cho s3.amazonaws.com trên SNS / SQS / Lambda, hoặc hai rule cùng prefix / suffix chồng lấn cùng loại sự kiện.

#EFS

Thiết lậpLựa chọn
LoạiRegional (nhiều AZ, mặc định) hoặc One Zone (rẻ hơn, một AZ)
Throughput modeElastic (khuyên dùng: tự co giãn, trả theo dùng), Provisioned (đặt cố định), Bursting (theo dung lượng, có burst credit: BurstCreditBalance về 0 thì chậm)
Performance modeGeneral Purpose (độ trễ thấp, mặc định), Max I/O (đời cũ, độ trễ cao hơn)
Storage classStandard, Infrequent Access, Archive; lifecycle policy chuyển file không truy cập sau N ngày, và chuyển lại Standard khi được đọc
  • Mount target: mỗi AZ một cái, có security group; cần cho phép TCP 2049 từ client.
  • EFS access points: điểm vào riêng cho từng ứng dụng (thư mục gốc, user POSIX). Kết hợp IAM authorization.
  • Mã hoá in transit: mount bằng amazon-efs-utils với tuỳ chọn tls. Mã hoá at rest chỉ bật lúc tạo.
  • EFS Replication sang Region / AZ khác (RPO khoảng 15 phút). Backup bằng AWS Backup.
  • Metric: PercentIOLimit (gần 100% ở General Purpose = chạm giới hạn I/O), BurstCreditBalance, ClientConnections, MeteredIOBytes.

Câu hỏi nhanh. Hệ thống log cần đọc tuần tự với throughput 400 MB/s, dung lượng 8 TiB, chi phí thấp nhất. Loại EBS?

st1 là HDD tối ưu throughput tuần tự (tới 500 MB/s), rẻ hơn SSD. sc1 chỉ tới 250 MB/s.

Câu hỏi nhanh. Ứng dụng tải file lên S3 bằng SSE-KMS bị ThrottlingException từ KMS khi tải hàng nghìn file nhỏ mỗi giây. Cách sửa tốt nhất?

Bucket Key cho S3 tạo key cấp bucket, giảm mạnh số request tới KMS.

Câu hỏi nhanh. EFS ở chế độ Bursting có hiệu năng giảm mạnh sau vài ngày tải cao, BurstCreditBalance về 0. Dung lượng chỉ 100 GB. Cách sửa ít công sức?

Bursting phụ thuộc dung lượng; file system nhỏ có baseline thấp. Elastic tự co giãn theo nhu cầu.

Câu hỏi nhanh. Văn phòng có file server Windows cần dung lượng gần vô hạn trên AWS nhưng người dùng vẫn truy cập qua SMB với độ trễ thấp cho file hay dùng. Dịch vụ?

File Gateway giữ cache tại chỗ, dữ liệu đầy đủ ở AWS, giao thức SMB không đổi.

Giám sát và cảnh báo bảo mật

GuardDuty chi tiết, Security Hub, Macie, Inspector, Detective, Security Lake, Config conformance pack, metric / alarm / dashboard bảo mật, tập trung hoá cho Organization.

Học xong bài này bạn sẽ:
  • Phân biệt rõ các dịch vụ phát hiện
  • Bật tập trung cho cả Organization
  • Dựng cảnh báo và đánh giá tự động

#GuardDuty chuyên sâu

Bật và quản lý

  • Dịch vụ Regional: bật ở mọi Region, kể cả Region không dùng (hoặc chặn Region đó bằng SCP). Kẻ tấn công rất hay chạy máy đào coin ở Region ít ai để ý.
  • Organization: management account chỉ định delegated administrator (account Security Tooling), bật auto-enable cho account mới và chọn auto-enable từng protection plan.
  • GuardDuty tự đọc CloudTrail, VPC Flow Logs, DNS logs qua luồng nội bộ: không cần bạn bật trail / flow log, không tốn phí lưu log đó. DNS log chỉ có khi instance dùng Route 53 Resolver (DNS .2); dùng DNS riêng thì GuardDuty mất nguồn DNS.
  • Tắt GuardDuty (suspend / disable) xoá hết finding: chặn bằng SCP.

Giảm nhiễu và mở rộng

  • Trusted IP list: IP tin cậy (không sinh finding cho chúng). Threat IP list: IP xấu của riêng bạn. Danh sách đặt trong S3, chỉ admin account quản lý.
  • Suppression rule: tự lưu trữ (archive) finding khớp điều kiện, ví dụ finding của máy quét lỗ hổng nội bộ. Finding vẫn được tạo nhưng không làm phiền.
  • Xuất finding ra S3 (mã hoá KMS, bắt buộc) để lưu lâu (GuardDuty giữ 90 ngày).
  • Finding gửi EventBridge (mỗi finding mới ngay, cập nhật lặp lại theo tần suất 15 phút / 1 giờ / 6 giờ) và Security Hub.

#Security Hub

  • Security Hub CSPM: chạy các security control theo tiêu chuẩn: AWS Foundational Security Best Practices (FSBP), CIS AWS Foundations Benchmark, PCI DSS, NIST SP 800-53, AWS Resource Tagging Standard. Mỗi control dựa trên một Config rule (service-linked), nên phải bật Config với các loại tài nguyên liên quan.
  • Định dạng finding: ASFF (AWS Security Finding Format) và OCSF (trong Security Hub mới). Nhận finding từ hơn 70 sản phẩm bên thứ ba và gửi ra SIEM / ticketing (Jira, ServiceNow).
  • Cross-Region aggregation: chọn một Region tổng hợp. Central configuration: từ delegated admin tạo configuration policy (bật / tắt Security Hub, tiêu chuẩn, control) cho từng OU / account.
  • Automation rules: tự sửa trường của finding khi khớp điều kiện (đổi severity, thêm note, chuyển workflow status sang SUPPRESSED cho finding chấp nhận rủi ro).
  • Custom actions: nút bấm trên console gửi finding được chọn tới EventBridge (người phân tích chọn "cô lập" chẳng hạn).
  • Insights: nhóm finding (top tài nguyên có nhiều finding critical). Security score theo tiêu chuẩn.
  • Security Hub (bản mới) còn tương quan tín hiệu từ GuardDuty, Inspector, CSPM thành exposure finding (tài nguyên vừa có lỗ hổng vừa mở ra Internet vừa có quyền cao).

#Inspector, Macie, Detective

Amazon Inspector

  • Bật một lần, quét liên tục (khi có CVE mới, khi có thay đổi). EC2 cần là SSM managed node (hoặc dùng agentless scan qua snapshot EBS). ECR: enhanced scanning thay basic scanning. Lambda: standard (thư viện) và code scanning (lỗi bảo mật trong code).
  • Inspector score: điểm CVSS điều chỉnh theo bối cảnh (có network reachable không, có exploit công khai không).
  • Network reachability finding: cổng mở ra Internet qua IGW / ELB, không cần agent.
  • CIS scan trên EC2, SBOM export, CI/CD integration (quét image trong pipeline trước khi push).
  • Suppression rule cho lỗ hổng đã chấp nhận rủi ro.

Amazon Macie

  • Automated sensitive data discovery: lấy mẫu object liên tục trên mọi bucket, chi phí thấp, cho bản đồ độ nhạy của bucket.
  • Sensitive data discovery job: quét đầy đủ bucket chọn trước, theo lịch hoặc một lần.
  • Managed data identifier (thẻ tín dụng, hộ chiếu, khoá AWS...) và custom data identifier (regex + từ khoá xung quanh), allow list để bỏ qua giá trị mẫu.
  • Finding hai loại: policy finding (bucket public, tắt mã hoá, chia sẻ ra ngoài) và sensitive data finding.
  • Bucket mã hoá SSE-KMS bằng customer managed key: key policy phải cho service-linked role của Macie dùng key, nếu không Macie không đọc được object.
  • Kết quả chi tiết (sensitive data discovery results) lưu ra S3 (bắt buộc KMS).

Amazon Detective

  • Tự thu thập và lập behavior graph từ CloudTrail, Flow Logs, GuardDuty, EKS audit, Security Hub; giữ tới 1 năm.
  • Từ một finding GuardDuty → "Investigate in Detective": dòng thời gian, IP, user agent, các API đã gọi, so với hành vi bình thường (baseline), finding groups gom finding liên quan.
  • Phải bật GuardDuty trước (ít nhất 48 giờ dữ liệu). Quản lý bằng delegated admin.

#Security Lake

  • Tạo data lake trên S3 ở account của bạn (thường là Log Archive), dùng Lake Formation và Glue để quản lý quyền và catalog.
  • Nguồn có sẵn (native): CloudTrail management / data events, VPC Flow Logs, Route 53 Resolver query logs, Security Hub findings, EKS audit logs, WAF logs. Nguồn tuỳ chỉnh: bất kỳ hệ thống nào ghi được dữ liệu dạng OCSF + Parquet.
  • Chọn rollup Region để gom dữ liệu nhiều Region, đặt retention và lifecycle chuyển lớp lưu trữ.
  • Subscriber: data access (đọc trực tiếp từ S3, nhận thông báo SQS khi có dữ liệu mới) hoặc query access (truy vấn qua Athena / Lake Formation resource share). Dùng cho SIEM bên thứ ba (Splunk, Sentinel...), OpenSearch, QuickSight.

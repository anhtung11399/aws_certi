SCS-C03Domain 3 · Infrastructure Security (18%)Bài 0765 phút

Bảo mật mạng: phân đoạn, firewall, kết nối lai

SG, NACL, Network Firewall, DNS Firewall, phân đoạn north-south / east-west, isolated subnet, VPN, Direct Connect, MACsec, Verified Access, Network Access Analyzer.

Học xong bài này bạn sẽ:
  • Thiết kế phân đoạn mạng an toàn
  • Chọn kết nối lai an toàn
  • Tìm đường truy cập thừa

#Network Firewall chi tiết

  • Firewall policy gồm stateless rule group (xét trước, theo 5-tuple, hành động pass / drop / forward to stateful) và stateful rule group (domain list, 5-tuple, Suricata rule). Thứ tự stateful: strict order (khuyên dùng, có default drop) hoặc action order.
  • Domain list: allowlist / denylist tên miền cho HTTP (Host) và TLS (SNI), ví dụ chỉ cho .amazonaws.com, .windowsupdate.com.
  • TLS inspection: giải mã, kiểm tra, mã hoá lại (cần chứng chỉ trong ACM).
  • Managed threat signatures của AWS (malware, botnet, khai thác lỗ hổng).
  • Logs: alert, flow, TLS về S3 / CloudWatch Logs / Firehose.
  • Mô hình triển khai: distributed (firewall trong từng VPC) hoặc centralized (inspection VPC nối TGW, bật appliance mode trên attachment để traffic hai chiều đi cùng AZ). Network Firewall cũng gắn trực tiếp được vào TGW.
  • Lỗi hay gặp: định tuyến bất đối xứng (đi qua firewall một chiều, về không qua) → stateful rule drop; quên route từ IGW (edge association / ingress routing) về firewall endpoint.

#Phân đoạn mạng

  • North-south (vào / ra Internet hoặc on-premises): WAF, Shield, Network Firewall ở biên, NAT, egress filtering.
  • East-west (giữa các VPC / subnet / ứng dụng bên trong): SG theo tầng (web → app → db), NACL, Network Firewall trong inspection VPC, TGW route table tách môi trường, VPC Lattice (auth policy ở mức service).
  • Isolated subnet: không có route tới IGW / NAT; chỉ truy cập dịch vụ AWS qua VPC endpoint (database, workload xử lý dữ liệu nhạy cảm).
  • Tách môi trường bằng account và VPC riêng (blast radius), không chỉ bằng subnet.
  • Microsegmentation cho container: EKS network policy, ECS task với awsvpc (mỗi task một ENI, SG riêng).

#Tìm đường truy cập thừa

  • Network Access Analyzer: định nghĩa Network Access Scope ("mọi đường từ IGW tới subnet database", "traffic từ VPC dev tới VPC prod") và nhận danh sách đường đi vi phạm, kèm từng thành phần trên đường.
  • Inspector network reachability: EC2 có cổng mở ra Internet (qua IGW, ELB) mà không cần agent.
  • Reachability Analyzer: kiểm tra một cặp nguồn / đích cụ thể.
  • Security Hub / Config rule: SG mở 0.0.0.0/0 tới 22 / 3389, NACL cho mọi traffic, subnet tự gán public IP.
  • Firewall Manager security group policy: audit SG quá rộng, SG không dùng, áp SG chuẩn.

#Kiểm soát egress và chống rò dữ liệu

  • Không cho máy ra Internet tuỳ ý: isolated subnet + VPC endpoint, hoặc NAT + Network Firewall domain allowlist.
  • Endpoint policy cho S3: chỉ bucket của tổ chức (aws:ResourceOrgID) → chặn chép dữ liệu sang bucket cá nhân.
  • Bucket policy chỉ nhận qua endpoint (aws:SourceVpce), RCP để mọi bucket chỉ cho principal trong tổ chức.
  • DNS Firewall chặn DNS tunneling, GuardDuty phát hiện exfiltration qua DNS.

Câu hỏi nhanh. Network Firewall đặt trong inspection VPC nối Transit Gateway. Kết nối TCP giữa hai VPC bị drop ngẫu nhiên dù rule cho phép. Nguyên nhân thường gặp?

Stateful firewall cần thấy cả hai chiều của luồng; appliance mode giữ luồng ở cùng AZ.

Câu hỏi nhanh. Cần mã hoá lớp 2 trên kết nối Direct Connect 100 Gbps dedicated, không muốn overhead của IPsec. Chọn?

MACsec mã hoá ở lớp 2 với tốc độ đường truyền trên dedicated connection hỗ trợ.

Câu hỏi nhanh. Cần chứng minh không có đường mạng nào từ Internet tới các subnet chứa database ở 50 VPC. Công cụ?

Network Access Analyzer quét toàn bộ cấu hình theo phạm vi định nghĩa và liệt kê mọi đường vi phạm.

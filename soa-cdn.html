CloudFront, WAF, Shield và Global Accelerator

Cache behavior, cache / origin request policy, TTL, invalidation, OAC, signed URL, lỗi 4xx / 5xx, edge function, WAF rule, Shield, Global Accelerator.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Cấu hình CloudFront đúng cho S3 và ALB
  • Xử lý lỗi cache và lỗi origin
  • Bảo vệ ứng dụng ở biên

#CloudFront

  • Origin: S3, ALB, EC2, API Gateway, MediaStore, bất kỳ HTTP server. Origin group: failover sang origin phụ khi origin chính trả lỗi 5xx / 4xx đã chọn.
  • Cache behavior theo path pattern (/api/* không cache, /static/* cache lâu). Cache policy quyết định cache key (header, cookie, query string nào được tính). Origin request policy quyết định gửi gì về origin.
  • Cache key càng nhiều thành phần thì cache hit ratio càng thấp. Cache hit thấp: bỏ bớt header / cookie / query string không cần trong cache key.
  • TTL: min / default / max, origin gửi Cache-Control: max-age. Nội dung đổi mà người dùng vẫn thấy bản cũ: invalidation (/* hoặc đường dẫn cụ thể, tính phí sau 1.000 path / tháng) hoặc tốt hơn là đổi tên file theo phiên bản (app.v42.js).
  • Origin Access Control (OAC): chỉ cho CloudFront đọc bucket S3 private, bucket policy cho phép principal cloudfront.amazonaws.com với điều kiện AWS:SourceArn là distribution. OAI là cách cũ.
  • Bucket mã hoá SSE-KMS: key policy phải cho CloudFront (qua OAC) dùng key.
  • Nội dung riêng tư: signed URL (một file) / signed cookies (nhiều file).
  • Geo restriction chặn theo quốc gia. Field-level encryption mã hoá trường nhạy cảm.
  • Logs: standard logs về S3, real-time logs qua Kinesis. Metric: CacheHitRate (bật thêm metric), 4xxErrorRate, 5xxErrorRate, OriginLatency.
  • Chạy code ở edge: CloudFront Functions (rất nhẹ, viewer request / response, sửa header, redirect) và Lambda@Edge (nặng hơn, gọi được mạng, có cả origin request / response).

Các thiết lập quan trọng khác

  • Price class: giới hạn edge location (All, 200, 100) để giảm chi phí.
  • Origin Shield: một tầng cache trung tâm trước origin, tăng tỉ lệ hit, giảm tải origin khi nhiều edge cùng hỏi.
  • Origin timeouts: connection timeout, response timeout (mặc định 30 giây, tăng được), số lần thử kết nối.
  • Viewer protocol policy: Redirect HTTP to HTTPS / HTTPS only. Origin protocol policy: HTTP only / HTTPS only / match viewer. Tới ALB bằng HTTPS thì chứng chỉ ALB phải khớp tên miền mà CloudFront gửi.
  • Response headers policy: thêm header bảo mật (HSTS, CSP), CORS.
  • Custom error responses: trả trang lỗi riêng, đặt TTL cache lỗi (mặc định 10 giây), SPA trả index.html cho 403 / 404.
  • Continuous deployment: staging distribution nhận một phần traffic để thử cấu hình mới.
  • VPC origins: dùng ALB / EC2 trong private subnet làm origin, không cần mở ra Internet.
  • Tên miền riêng: thêm alternate domain name (CNAME) + chứng chỉ ACM ở us-east-1, Route 53 alias tới distribution.

Đọc lỗi CloudFront

LỗiThường do
403 với S3 originBucket policy chưa cho OAC, object không tồn tại (S3 trả 403 thay 404 khi không có quyền list), thiếu quyền KMS, geo restriction, WAF chặn
502CloudFront không bắt tay TLS được với origin: chứng chỉ origin hết hạn / không khớp tên miền
504Origin không trả lời kịp (origin response timeout, mặc định 30 giây), security group của ALB không cho dải IP của CloudFront (dùng managed prefix list com.amazonaws.global.cloudfront.origin-facing)

Giám sát CloudFront

  • Metric (global, xem ở us-east-1): Requests, BytesDownloaded, 4xxErrorRate, 5xxErrorRate, TotalErrorRate; bật additional metrics để có CacheHitRate, OriginLatency, mã lỗi chi tiết.
  • Standard logs (về S3 / CloudWatch Logs / Firehose), real-time logs (Kinesis Data Streams), báo cáo cache / popular objects / viewers trên console.
  • Header response X-Cache: Hit from cloudfront / Miss from cloudfront để kiểm tra cache.

#WAF, Shield, Global Accelerator

  • AWS WAF: gắn vào CloudFront, ALB, API Gateway, AppSync, Cognito. Web ACL gồm rule: managed rule groups (OWASP, IP xấu, bot), rate-based rule (chặn IP gửi quá N request / 5 phút), chặn theo quốc gia, IP set, regex. Log WAF về CloudWatch Logs / S3 / Firehose. Thử rule ở chế độ Count trước khi Block.
  • Shield Standard: miễn phí, chống DDoS layer 3/4. Shield Advanced: trả phí, có đội SRT (Shield Response Team) hỗ trợ, bảo vệ chi phí khi scale do DDoS, tự tạo rule WAF giảm nhẹ tấn công layer 7.
  • WAF chi tiết: web ACL có default action (Allow / Block), rule xét theo priority; managed rule group có thể đặt rule con sang Count để tránh chặn nhầm; scope-down statement giới hạn rule cho một phần request; label để rule sau dùng kết quả rule trước; custom response; giới hạn kích thước body được kiểm tra (mặc định 8 KB với ALB, 16 KB với CloudFront, tăng được).
  • Xem request bị chặn: sampled requests trên console, WAF logs, metric BlockedRequests / AllowedRequests theo rule.
  • Firewall Manager áp web ACL chung cho mọi ALB / CloudFront của Organization.
  • Global Accelerator: 2 IP anycast tĩnh, đi trên mạng của AWS tới endpoint gần nhất (ALB, NLB, EC2, EIP), failover giữa Region trong vài giây. Hợp với TCP / UDP, game, khi cần IP tĩnh cho whitelist. CloudFront thì cache nội dung HTTP.

Câu hỏi nhanh. Website tĩnh trên S3 sau CloudFront. Sau khi bật OAC và chặn public access, người dùng nhận 403. Thiếu gì?

Với OAC, bucket policy phải cấp quyền cho dịch vụ CloudFront gắn với đúng distribution.

Câu hỏi nhanh. Cache hit ratio của CloudFront chỉ 15%. Phân tích cho thấy cache key gồm mọi header và mọi cookie. Cách cải thiện?

Mỗi giá trị khác của header / cookie tạo một bản cache riêng. Cache key gọn thì tỉ lệ hit tăng.

CloudWatch Logs, tracing và observability

Log group, retention, metric filter, Logs Insights, subscription, export, Embedded Metric Format, X-Ray, Application Signals, Synthetics, RUM, Container / Lambda Insights, Prometheus, Grafana, CloudTrail cho vận hành.

Video bài giảng sẽ được cập nhật sau
Học xong bài này bạn sẽ:
  • Đưa log từ mọi nguồn vào CloudWatch và phân tích được
  • Chọn đúng công cụ tracing / giám sát người dùng
  • Gom log nhiều account

#Cấu trúc CloudWatch Logs

Thành phầnGiải thích
Log eventMột dòng log: timestamp + nội dung (tối đa 1 MB)
Log streamChuỗi event từ một nguồn: một instance, một container, một lần chạy Lambda
Log groupNhóm stream cùng loại, nơi đặt retention, KMS key, metric filter, subscription filter, quyền truy cập
Log classStandard (đầy đủ tính năng) hoặc Infrequent Access (rẻ hơn khoảng 50% khi ingest, không có metric filter / Live Tail / subscription đầy đủ, vẫn query bằng Logs Insights)
  • Retention mặc định Never expire: tốn tiền dần. Đặt retention (1 ngày tới 10 năm) cho mọi log group. Kiểm tra bằng Config rule cw-loggroup-retention-period-check.
  • Mã hoá: luôn được mã hoá bởi AWS. Muốn tự kiểm soát key: gắn KMS key, key policy cho logs.<region>.amazonaws.com với điều kiện kms:EncryptionContext:aws:logs:arn.
  • Data protection policy: tự phát hiện và che (mask) dữ liệu nhạy cảm trong log (email, số thẻ, khoá AWS). Người có quyền logs:Unmask mới xem được bản gốc.

#Metric filter

  • Biến log thành metric: đếm số dòng khớp, hoặc trích một giá trị số trong log (ví dụ thời gian xử lý).
  • Cú pháp mẫu: chuỗi đơn giản "ERROR", nhiều từ "ERROR" "payment" (AND), ?ERROR ?WARN (OR), JSON { $.status = 500 }, khoảng trắng [ip, user, ..., status=5*, size].
  • Đặt default value (ví dụ 0) để metric có điểm dữ liệu cả khi không có dòng khớp, tránh alarm ở INSUFFICIENT_DATA.
  • Chỉ xử lý log mới sau khi tạo filter. Muốn phân tích dữ liệu cũ dùng Logs Insights.
  • Mẫu kinh điển (CIS): CloudTrail → CloudWatch Logs → metric filter cho ConsoleLogin thất bại, đổi security group, dùng root → alarm → SNS.

#Logs Insights

Ví dụ truy vấn
# Top 20 request chậm nhất trong log JSON của API
fields @timestamp, path, duration
| filter duration > 1000
| sort duration desc
| limit 20

# Số lỗi theo từng phút
filter @message like /ERROR/
| stats count(*) as errors by bin(1m)

# Lambda: thời gian chạy và bộ nhớ dùng
filter @type = "REPORT"
| stats avg(@duration), max(@maxMemoryUsed / 1000 / 1000) as maxMB by bin(5m)

# Tách trường từ log văn bản
parse @message "user=* action=*" as user, action
| stats count(*) by action
  • Truy vấn được nhiều log group cùng lúc (tới 50), kể cả từ nhiều account qua cross-account observability.
  • Hỗ trợ cả cú pháp OpenSearch PPL / SQL. Có trợ lý viết truy vấn bằng ngôn ngữ tự nhiên.
  • Lưu truy vấn, đưa kết quả lên dashboard. Tính tiền theo lượng dữ liệu quét: thu hẹp khoảng thời gian.
  • Contributor Insights: tìm "ai đóng góp nhiều nhất" (top IP, top URL lỗi) liên tục, có metric và alarm. Pattern analysis: tự gom log thành mẫu để thấy lỗi lạ.
  • Live Tail: xem log trực tiếp khi gỡ lỗi.

#Đưa log đi nơi khác

CáchĐộ trễDùng khi
Subscription filter → Kinesis Data Streams / Firehose / Lambda / OpenSearchGần thời gian thựcPhân tích liên tục, SIEM, gom nhiều account về account trung tâm (destination + resource policy). Mỗi log group tối đa 2 subscription filter
Account-level subscriptionGần thời gian thựcMột cấu hình cho mọi log group của account
Export to S3 (CreateExportTask)Tới 12 giờLưu trữ lô, không cần thời gian thực. Bucket không được mã hoá SSE-KMS kiểu cũ trong một số trường hợp, cần bucket policy cho logs
Firehose → S3 → lifecycle GlacierVài phútLưu lâu năm rẻ nhất

"Gom log của nhiều account về một account log trung tâm gần thời gian thực" → subscription filter + cross-account destination (Kinesis / Firehose). "Lưu log 7 năm chi phí thấp" → đưa sang S3 + lifecycle Glacier, đặt retention ngắn cho log group.

#Tracing và giám sát ứng dụng

Công cụTrả lời câu hỏi
AWS X-RayMột request đi qua API Gateway, Lambda, DynamoDB, dịch vụ ngoài... chậm ở đâu, lỗi ở đâu. Service map, trace, segment / subsegment, sampling rule. Cần SDK / OpenTelemetry trong ứng dụng, X-Ray daemon / agent trên EC2 / ECS, bật active tracing cho Lambda và API Gateway
CloudWatch Application SignalsAPM tự động (dựa trên OpenTelemetry): latency, lỗi, SLO cho từng dịch vụ và từng API mà ít phải sửa code
CloudWatch SyntheticsCanary (script Node.js / Python, Puppeteer / Selenium) chạy theo lịch, mô phỏng người dùng: kiểm tra trang còn sống, luồng đăng nhập, API, liên kết hỏng, so sánh ảnh chụp
CloudWatch RUMĐo trải nghiệm người dùng thật trên trình duyệt: thời gian tải trang, lỗi JavaScript
Container InsightsMetric CPU / RAM / mạng theo cluster, service, task, pod (ECS, EKS, Kubernetes trên EC2)
Lambda InsightsMetric chi tiết của Lambda (CPU, RAM, cold start) qua Lambda extension
Internet Monitor / Network MonitorChất lượng Internet tới người dùng ở các vùng / chất lượng kết nối hybrid
Amazon Managed Service for PrometheusPrometheus được quản lý cho EKS / Kubernetes, truy vấn PromQL
Amazon Managed GrafanaGrafana được quản lý, đăng nhập bằng Identity Center, nguồn dữ liệu CloudWatch, Prometheus, X-Ray, OpenSearch...
CloudWatch Investigations / Amazon QTrợ lý AI gợi ý nguyên nhân khi có sự cố dựa trên metric, log, trace, thay đổi gần đây

Phân biệt nhanh: Synthetics = người dùng giả chạy theo lịch (biết lỗi trước khi khách gặp). RUM = người dùng thật. X-Ray / Application Signals = bên trong hệ thống chậm ở đâu.

#CloudTrail cho đội vận hành

  • Event history: 90 ngày management events, miễn phí, mọi Region, tra theo user, tên sự kiện, tài nguyên.
  • Trail: lưu lâu dài về S3 (và CloudWatch Logs). Trail multi-Region, organization trail.
  • Management events (mặc định), data events (S3 object, Lambda invoke, DynamoDB item: phải bật, tính phí), Insights events (phát hiện số API call / lỗi bất thường, ví dụ ai đó gọi TerminateInstances hàng loạt).
  • CloudTrail Lake: kho event truy vấn bằng SQL, giữ tới 10 năm.
  • Trả lời câu "ai đã làm X lúc nào": tìm trong Event history hoặc dùng Athena / CloudTrail Lake trên trail.
  • Trường hữu ích: userIdentity, eventName, sourceIPAddress, userAgent, errorCode (AccessDenied), requestParameters.
  • Kết hợp Config: Config cho biết cấu hình trước và sau, CloudTrail cho biết ai đổi.
